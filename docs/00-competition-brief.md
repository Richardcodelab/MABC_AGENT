# MABC 2026 — 예선 규칙 (확정본)

> Making AI Beneficial Challenge 2026 · 주최: 업스테이지 + 타임리
> **§1~§3은 참가자가 공식 안내에서 직접 가져온 확정 규칙.** §4는 기사 기반 참고 정보(신뢰도 낮음).
> 최종 갱신 2026-08-27

## 1. 제출 규격

예선 제출은 **① 스토어 등록 + ② 구글 폼 제출을 모두 완료**해야 정식 접수된다.
**하나라도 누락 시 평가 대상 제외.**

| 구분 | 규격 |
|---|---|
| **제출 기간** | 2026-08-18(화) ~ **2026-08-31(월) 18:00 KST (시간 엄수)** |
| **제출 방법 ①** | 타임리 스토어 업로드 — 팀원 **각자 계정**으로, 인당 최대 3개, 태그 **`mabc-final` 필수** |
| **제출 방법 ②** | 구글 폼 — **팀장이 대표로** 작성 + **`skill.zip` 첨부**. 스킬 1개당 폼 1회 작성. 폼에 '스킬을 업로드한 팀원 계정' 기재 필수 |
| **실행 환경** | 타임리 AI **`Making AI Beneficial Challenge` 스페이스** × **Solar Pro 4** 모델 한정. 타 스페이스/타 모델 사용 시 **실격** |
| **제출 수** | 개인 **최대 3개** / 팀(최대 3인) **최대 9개** (인원수 × 3) |
| **대표작 반영** | 제출작 중 **가장 점수가 높은 1개**만 대표작으로 평가 |
| **중복/추가 제출** | 마감 시각 기준 **가장 최근 폼 N개만** 반영 (개인 최신 3 / 팀 최신 9) |
| **외부 API 사용 시** | API Key를 **코드에 절대 넣지 말고** 구글 폼 제공 엑셀 양식으로 별도 첨부 + 동의 체크. 제출한 Key는 평가 목적 **최대 3회 실행** 후 즉시 폐기 |

## 2. 실격 조건

제재는 **[해당 결과물 실격] / [개인 자격 박탈] / [팀 전체 실격]** 3단계.

### [해당 결과물 실격] — 절차 누락 및 미동작
- 스토어 태그 `mabc-final` 누락
- 구글 폼 미작성 / `.zip` 미첨부
- 마감 시각 초과
- **심사 시점에 실행 오류가 발생하는 스킬**

> 해당 스킬만 제외되고 나머지 정상 스킬은 평가된다.

### [개인 자격 박탈] — 참가 자격 불충족
- 연령·신원·소속 등 허위 사실

### [결과물 또는 팀 전체 실격] — 모델 및 보안 위반
- **Solar Pro 4 외 타 모델 / 외부 LLM API 호출**
- 코드 내 **API Key·개인정보 하드코딩**
- 저작권·법규 위반 콘텐츠

### [팀 전체 실격] — 중대한 부정행위
- 자동화 스크립트 부정 제작, 다중 계정, 타인 아이디어·스킬 도용/표절
- 심사 청탁·방해, 운영진 검증 요청 불응

## 3. 제출 전 체크리스트

## 4. 예선 심사 기준 (100점 만점)

심사위원단이 제출된 **`skill.zip` 파일과 `SKILL.md` 문서를 기반으로** 심사한다.
→ **`SKILL.md` 자체가 심사 대상 문서다. 문서를 잘 쓰는 것이 곧 점수다.**

| 평가 항목 | 배점 | 핵심 평가 질문 |
|---|---|---|
| **문제정의 및 실용성** | **30** | 실제로 겪는 구체적 문제를 해결하는가 / **해결하려는 반복 과업의 빈도·시간이 명확한가** |
| **설계 체계성** | **30** | **예외 입력 및 실패 상황 처리가 지침에 반영되었는가** / 역할·지시·출력 구조가 체계적인가 |
| **재현 가능성** | **20** | 처음 보는 새 입력으로도 의도대로 동작하는가 / 오류 없이 안정적으로 구동되는가 |
| **독창성** | **20** | 문제 접근·솔루션 설계에 독창성이 있는가 / **기존 스토어 스킬 대비 차별점이 명확한가** |

### 동점자 처리 ⭐
**동점 시 제출 일시가 빠른 응답에 우선순위.** 완성되면 **조기 제출**할 것.

### 결선 진출 발표
**2026년 9월 7일(월)** — 50팀 대상 개별 연락

## 5. 제출 절차 (3-Step)

### Step 1. 타임리 스토어 업로드
1. 스킬 편집 창에서 **[내려받기]** → `skill.zip`을 PC에 저장
2. 우측 상단 **[스토어에 올리기]** 클릭
3. 태그 입력란에 **`mabc-final`** 입력 후 업로드

### Step 2. 구글 폼 작성 + `skill.zip` 첨부
1. **[MABC 2026 예선 과제 제출 폼]** 접속
2. 대회 신청 이메일, 타임리 계정, **스킬 정보(스킬명 / 1줄 요약 / 상세 설명)** 작성
3. Step 1의 `skill.zip`을 **파일명 그대로** 첨부 후 제출

> 구글 폼에도 **1줄 요약과 상세 설명**을 쓴다. SKILL.md와 별개로 이 텍스트도 준비할 것.

### Step 3. 제출 완료 확인
- 스토어 **[내가 올린]** 탭에서 `승인 대기` 또는 게시 상태 확인
- 구글 폼 제출 완료 메시지 + 작성 사본 이메일 확인

> ⚠️ **스토어만 올리고 폼을 안 쓰거나, 폼만 쓰고 스토어에 안 올리면 평가 대상 제외.**

## 9. 규칙에서 도출한 전략

### 9-1. 외부 API — 허용되지만 폴백 필수 ⭐

**제5조 3항이 공공데이터포털 API를 명시적으로 허용한다.** 금지가 아니라 선택의 문제다.

다만 리스크는 실재한다:
- **재현 가능성 20점** = "오류 없이 안정적으로 구동되는가"
- **제12조 3호** = "제출물이 정상 동작하지 않는 경우" → 해당 스킬 실격
- 심사 시 제출한 API Key로 **최대 3회만 실행**

→ **판단**: 외부 API를 쓴다면 **호출 실패 시에도 스킬이 완결된 결과를 내도록 폴백을 반드시 설계**한다.
API 없이는 아무것도 못 하는 구조라면 쓰지 않는다.

→ **우리 스킬의 경우**: NCS API는 쓰지 않는다. 규정 때문이 아니라 **입자 크기가 안 맞기 때문**이다
(`docs/02-ncs-decision.md` 참조). KSA는 사용자가 붙여넣는 직무기술서에서 받는다.

### 9-2. 각 스킬은 단독으로 완결되어야 한다 ⭐

"제출작 중 **최고점 1개만** 대표작" 규칙이 공식 확인되었다.
파이프라인으로 쪼개면 대표작 하나의 완성도가 떨어진다.

→ 3개 스킬 각각이 **혼자서 심사받아도 완결**되도록 설계. (`docs/01-idea-design.md` 참조)

### 9-3. 견고성이 곧 생존이다 ⭐

**"심사 시점에 실행 오류가 발생하는 스킬"은 실격**이고,
심사는 **새 대화창에서 처음 보는 입력**으로 이뤄진다. 심사자가 무엇을 넣을지 알 수 없다.

방어해야 할 상황:
- 입력이 아예 없음 / 한쪽만 있음
- 이력서 대신 엉뚱한 문서
- 너무 짧거나(한 줄) 너무 김
- 외국어, 표 깨진 텍스트, PDF 복사 시 줄바꿈 깨짐

→ 모든 스킬에 **입력 검증과 폴백 동작**을 명시한다. 오류로 멈추지 말고 **부분 결과라도 낼 것.**

### 9-4. 제출 슬롯 — 채우되 "유사 반복"은 금지 ⚠️

개인 3개 / 3인 팀 9개. 최고점 1개만 반영되므로 더 내는 것 자체는 이득이다.

**단 제6조 2항**: *"실질적 기능이 없거나 동일·유사한 제출물을 형식적으로 반복 제출하는 경우,
해당 제출물은 심사 및 집계에서 제외될 수 있다."*

→ 슬롯 채우기용 변형 복제는 **역효과**다. 각 스킬은 **문제 정의부터 달라야** 한다.

→ **우리 3개의 위험 지점**: 1번(이력서 추출)과 2번(공고 추출)이 "추출 스킬"로 유사하게 보일 수 있다.
**두 스킬은 해결하는 문제도, 처리 로직도, 출력 형태도 다르다는 점을 SKILL.md에서 명시적으로 드러낸다.**
(이력서 = 과장 보정 + 근거 검증 / 공고 = 축약 복원 + 숨은 요구 추론)

### 9-5. 저작권 주의

실제 채용공고 원문을 스킬 안에 예시로 박아 넣지 않는다. 예시는 전부 창작하거나 각색한다.
샘플 이력서도 전부 가상 인물로 만든다. (실명·연락처 금지)

### 9-6. 최종 스킬은 반드시 타임리에서 제작한다 🚨

**제5조 1항**: *"제출물은 타임리 서비스 내 지정한 MABC 워크스페이스에서 제작한 결과물을 이야기한다.
**타 서비스를 통해 만든 skill은 실격처리 한다.**"*

→ **이 저장소의 `SKILL.md`는 원고다.** 로컬에서 zip으로 압축해 제출하면 안 된다.
→ 반드시 **타임리 편집창에 옮겨 붙여 거기서 제작·테스트**하고, **[내려받기]한 `skill.zip`을 제출**한다.

### 9-7. 조기 제출 ⭐

**제5조 7항 및 심사 안내**: 동점 시 **제출 일시가 빠른 쪽 우선**.
또 제16조 3항이 마감 임박 장애를 경고한다.

→ 완성되는 즉시 제출한다. 마감 직전까지 다듬지 않는다.
→ 결선 발표는 **9월 7일(월)** 개별 연락.
