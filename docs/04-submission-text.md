# 구글 폼 제출용 텍스트

> 구글 폼에 **스킬명 / 1줄 요약 / 상세 설명**을 작성한다. `SKILL.md`와 별개 항목이다.
> 스킬 1개당 폼 1회. 아래를 그대로 복사해 쓰되, 타임리에서 최종 제작한 내용과 어긋나지 않는지 확인할 것.

## 스킬 1

**스킬명**
```
이력서 역량 진단기
```

**1줄 요약**
```
이력서에 쓴 경력이 실제로 증명되고 있는지 검증하고, 근거 없는 주장과 고쳐야 할 지점을 짚어줍니다.
```

**상세 설명**
```
구직자는 지원할 때마다 이력서를 고칩니다. 한 번에 1~2시간, 지원 시즌이면 주 3~6시간이
여기 들어갑니다. 그런데 그 시간 대부분이 문장을 다듬는 데 쓰입니다.

정작 중요한 질문은 따로 있습니다. "내가 쓴 경력이 이 문서에서 증명되고 있는가?"
"다양한 프로젝트를 수행하며 문제 해결 능력을 길렀습니다" — 본인은 경력을 썼다고
생각하지만 읽는 사람에게는 아무 정보도 전달되지 않습니다. 그리고 본인은 자기
이력서를 객관적으로 보지 못합니다.

이 스킬은 문장을 고쳐주지 않습니다. 대신 어느 문장이 증명에 실패했는지 짚어냅니다.

[동작 방식]
· 기술스택 나열 줄이 아니라 업무 서술 문장에서 역량을 추출합니다.
  "월 200만 건 로그 배치 파이프라인을 Python으로 설계" 한 문장에서
  기술(Python) + 직무능력(파이프라인 설계) + 도메인(대용량 처리) 세 개를 뽑습니다.
· 모든 판정에 이력서 원문을 인용합니다. 인용을 붙이지 못하면 그 역량은 인정하지 않습니다.
· 숙련도 1~5는 "어떤 표현이 나오면 몇 레벨"인지 표로 고정되어 있습니다.
  레벨 4 이상은 수치나 구체적 결과가 원문에 있어야만 인정합니다.
· 증명 실패 지점을 7개 유형으로 분류해 먼저 보여줍니다.
  근거 없는 주장 / 범위 흐린 표현 / 결과 없는 활동 / 나열만 된 스킬 /
  카테고리 편중 / 정체 구간 / 경력 공백

[다른 점]
LLM에 "첨삭해줘"라고 하면 문장이 매끄러워지고 없던 형용사가 붙어 과장이 늘어납니다.
이 스킬은 반대로, 고쳐주지 않고 짚어줍니다. 없는 사실을 만들지 않으니 면접에서
무너지지 않습니다. 판정 기준이 표로 고정되어 있어 같은 이력서는 몇 번을 돌려도
같은 결과가 나옵니다.

[예외 처리]
빈 입력, 한두 줄만 입력, 이력서가 아닌 문서, 신입·무경력, PDF 복사로 깨진 텍스트,
외국어 이력서, 과도한 분량, 판정 근거가 애매한 경우 등 10가지 상황을 지침에 명시했습니다.
원칙은 하나입니다 — 오류로 멈추지 않고 부분 결과라도 냅니다.
개인정보(이름·연락처·주소·생년월일)는 결과에 출력하지 않습니다.
```

## 스킬 2

**스킬명**
```
채용공고 해부기
```

**1줄 요약**
```
채용공고의 자격요건에 안 쓰인 숨은 요구사항을 담당업무에서 복원하고, 이 공고가 진짜 찾는 사람을 판정합니다.
```

**상세 설명**
```
채용공고 1건을 꼼꼼히 읽는 데 15~20분, 주 10건이면 주 3시간입니다.
그런데 그 시간을 쓰고도 두 가지가 계속 일어납니다.

하나. 자격요건만 읽고 판단합니다. 공고는 축약된 문서라 담당업무 세 줄에 실제로는
열 개의 역량이 숨어 있습니다. "유관부서와 협업하여 요구사항을 정의" 한 줄이
이해관계자 조율 + 비기술 직군과의 커뮤니케이션 + 요구사항 문서화를 요구하는데
자격요건에는 한 글자도 없습니다.

둘. 면접에서 막힙니다. "담당업무에 있던 그 일, 해보셨어요?" — 대비가 안 됩니다.

이 스킬은 공고 한 건을 필수 / 우대 / 숨은 요구사항으로 분해하고,
어디서 검증당할지까지 알려줍니다.

[동작 방식]
· 자격요건 항목에 여러 역량이 섞여 있으면 쪼갭니다.
  "Python 기반 파이프라인 구축 및 운영 경험 3년 이상"
  → Python + 파이프라인 구축 + 운영·모니터링 + 경력 3년, 네 개로 분해
· 담당업무 문장에서 명시되지 않은 요구를 복원합니다. 8가지 복원 패턴을 표로 제공합니다.
  "신규 서비스 런칭" → 0→1 경험, 불확실성 하 의사결정
  "소수 정예" → 넓은 업무 범위, 직무 경계 모호함 감수
· 추론한 항목에는 반드시 (추론) 표시와 근거 인용을 붙여, 공고에 있는 말과 구분합니다.
· 직함을 믿지 않고 요구역량의 무게중심으로 실제 직무를 판정합니다.
  직함은 "데이터 분석가"인데 요구역량 대부분이 파이프라인 구축이면
  실제로는 데이터 엔지니어라고 알려줍니다.
· 공공기관 채용공고의 NCS 직무기술서를 인식합니다. 능력단위와 지식·기술·태도가
  명시되어 있으면 추론하지 않고 그대로 채택하고, 태도(A)는 서류로 검증되지 않으므로
  요구역량 표에서 분리합니다.

[다른 점]
LLM에 "요약해줘"라고 하면 공고를 줄여서 다시 써줍니다. 이미 있는 내용이라
읽는 시간은 줄지만 판단은 나아지지 않습니다.
이 스킬은 반대로 늘립니다. 공고에 없는 정보를 담당업무에서 복원합니다.

[예외 처리]
빈 입력, 공고가 아닌 문서, 담당업무만 있는 공고, 자격요건만 있는 공고, 두세 줄뿐인 공고,
여러 공고 동시 입력, 직함 모호, 필수/우대 구분 애매, 차별 소지 조건 발견, 외국어 공고,
표·HTML 복사로 깨진 텍스트 등 11가지 상황을 지침에 명시했습니다.
필수/우대 구분이 애매하면 우대로 둡니다 — 우대를 필수로 올리면 지원자가
불필요하게 포기하기 때문입니다.
나이·성별·용모 등 차별 소지 조건은 요구역량으로 등록하지 않고 주의 신호에 기록합니다.
```

## 스킬 3 ⭐ 대표작

**스킬명**
```
지원 판단 리포트
```

**1줄 요약**
```
이력서와 채용공고를 대조해 지원할 가치가 있는지, 어디가 막혀 있는지, 어느 문장을 강조할지 알려줍니다.
```

**상세 설명**
```
지원 한 건에 들어가는 시간은 공고를 읽는 시간이 아닙니다. 자기소개서 2~3시간,
이력서 맞춤 수정 1시간 — 한 건에 3~4시간입니다.
문제는 이 3~4시간을 쓸지 말지를 30분짜리 눈대중으로 결정한다는 것입니다.

그래서 양쪽으로 손해가 납니다.
· 막힌 곳에 지원합니다. 필수요건 하나가 완전히 비었는데 나머지가 좋아 보여서 씁니다.
· 되는 곳을 포기합니다. "ETL 경험자"를 보고, 내 "Python 배치 파이프라인 구축"이
  같은 일인 줄 모르고 넘깁니다.

원인은 같습니다. 표현이 다른 같은 역량을 사람이 눈으로 대조하지 못하는 것.

[동작 방식]
· 요구역량 하나하나에 대해 이력서에서 가장 가까운 보유 역량을 찾습니다.
  글자가 겹치지 않아도 같은 일이면 붙입니다.
  ETL ↔ Python 배치 파이프라인 (같음) / RDBMS ↔ MySQL 운영 (상위-하위)
  Kubernetes ↔ Docker (다름) / AWS ↔ GCP (부분)
  붙일 때마다 왜 같다고 봤는지 근거를 남겨, 억지 연결로 점수가 부풀지 않게 합니다.
· 필수/우대와 강조도에 따라 가중치를 다르게 주고,
  적합도 = Σ(가중치 × 충족률) ÷ Σ(가중치) × 100 으로 계산합니다.
  계산 표를 출력에 포함해, 점수에 동의하지 않으면 어느 항목 때문인지 짚을 수 있습니다.
· 필수요건이 하나라도 비어 있으면 총점이 높아도 별도로 경고합니다.
  평균에 묻히는 함정이 3~4시간을 날리는 가장 흔한 원인이기 때문입니다.
· 판단에서 끝내지 않습니다. 지원하기로 했다면 어느 문장을 공고 어휘로 다시 쓸지,
  막힌 곳을 어떻게 우회할지, 면접에서 뭘 물어볼지까지 냅니다.

[다른 점]
LLM에 "맞는지 봐줘"라고 하면 대체로 격려가 돌아옵니다. "충분히 경쟁력이 있어 보입니다."
읽고 나면 기분은 좋지만 지원할지 말지는 여전히 모르고, 다시 물으면 다른 답이 나옵니다.
이 스킬은 계산 과정을 공개하고, 막힌 항목을 총점과 분리해 경고하고,
결정이 아니라 판단 재료를 줍니다.

[예외 처리]
빈 입력, 한쪽만 입력, 문서 경계 불분명, 둘 다 이력서/둘 다 공고, JSON 형식 깨짐,
JSON 필드 누락, 요구역량 추출 실패, 직무 계열이 완전히 다른 경우, 신입·무경력,
대응이 애매한 경우, 가중치 합이 0인 경우(0으로 나누기) 등 12가지 상황을
지침에 명시했습니다.
한쪽만 넣어도 멈추지 않고 있는 쪽을 단독 분석해 돌려줍니다.
JSON 파싱에 실패해도 텍스트로 읽어 진행합니다.
```
