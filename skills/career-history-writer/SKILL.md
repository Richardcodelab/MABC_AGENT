# 경력기술서 작성기 (경력자용)

3단계로 진행한다: **[1단계] 재료 수집 → [2단계] 포맷 확정 → [3단계] 작성**

## 이 스킬이 푸는 문제

**[누가]** 이직을 준비하는 3년 이상 경력 지원자.

**[얼마나 자주]** 이직 시즌에 5~10개 회사에 지원한다. 대부분 경력기술서를 **한 번 써두고 돌려쓴다.**

**[어떤 작업에]** 회사별로 재직 기간·직책을 정리하고, 프로젝트를 떠올리고,
성과를 문장으로 만드는 작업. 경력 5년이면 회사 2~3곳에 프로젝트가 10개 이상이다.

**[시간은 얼마나]** 처음 한 번 쓰는 데 **4~8시간**. 그리고 지원처마다 고쳐야 하는데
시간이 없어서 **같은 문서를 그대로 낸다.** (경력 이직자 체감 기준 추정치)

**[무엇이 문제인가]** 두 가지가 동시에 일어난다.

**하나. 업무 나열이 된다.**
> "식품 카테고리 운영 담당" / "신규 브랜드 입점 업무" / "채널 관리"

무엇을 **했는지**는 있는데 무엇이 **좋아졌는지**가 없다.
검토자는 이 사람이 뭘 바꿔놨는지 알 수 없다. 경력기술서가 업무분장표가 된다.

**둘. 지원처와 무관하게 똑같은 문서를 낸다.**
서류 검토자는 문서 전체를 읽지 않는다. **맨 위 몇 줄로 "이 사람 = ○○ 전문가"인지 판단**한다.
그 몇 줄이 지원 직무와 안 맞으면 아래를 아무리 잘 써도 안 읽힌다.
그런데 회사마다 다시 큐레이션할 시간이 없어서 그대로 낸다.

이 스킬은 재료를 한 번 정리한 뒤, **지원처가 바뀌면 채용공고만 새로 넣어
핵심 역량과 큐레이션을 그 직무에 맞게 재구성**한다.

# 입력

```
① 인터뷰 결과지: (자소서 소재 은행 인터뷰의 결과지 / 없으면 비워두기)
② 기존 이력서·경력기술서: (있으면 전체 붙여넣기 — 오래된 버전도 괜찮음 / 없으면 비워두기)
③ 회사명 / 지원 직무:
   채용공고: (전체 붙여넣기 / 없으면 비워두기)
```

## 시작 전 확인

- **③(회사/직무)은 반드시 필요하다.** 없으면 진행하지 말고 요청한다.
- ①②가 **둘 다 비어 있으면** 안내하고 시작한다:
  `처음부터 인터뷰로 수집할게요. 회사 수 × 10분 정도 걸려요`
- ①②가 있으면 **거기서 최대한 채우고 빈 곳만 묻는다.** 같은 걸 두 번 묻지 않는다.

## 실행 모드

| 모드 | 언제 | 동작 |
|---|---|---|
| **작성 모드** (기본) | 재료가 있거나 인터뷰로 수집 | 3단계 진행 |
| **시연 모드** | "예시로 보여줘", "샘플", "어떻게 나오는지 보고 싶다" | **내장 샘플 결과지**로 완성된 경력기술서를 즉시 보여줌 |

> **시연 모드가 필요한 이유**: 이 스킬은 인터뷰 결과지를 전제로 한다.
> 결과지가 없는 사람은 아무것도 볼 수 없으므로, 가상 경력 지원자의 재료를 스스로 만들어
> 완성본을 보여준다. **"가상의 지원자로 만든 예시입니다"** 를 먼저 밝히고,
> 포맷 3종 중 하나를 골라 핵심 역량 요약 + 회사 블록 2개까지 보여준다.

# RULE 1. [1단계] 재료 수집

## ★ 재료의 출처

**①②③에 붙여넣은 내용과 이 대화에서 사용자가 직접 말한 것만 쓴다.**
이전 대화 기억이나 사용자에 대해 따로 알고 있는 정보(다른 회사·직무·자격 등)를
**절대 끌어오지 않는다.**

> 다른 사람의 경력이 섞이면 그대로 **허위 경력**이 된다.

## ★ 연차 정합성 확인

확보한 **재직 기간의 합계가 [지원 정보]의 총 경력 연차와 맞는지** 확인한다.
어긋나면 작성 전에 먼저 알린다:

```
연혁 합계는 9년인데 총 경력이 7년으로 되어 있어요. 어느 쪽이 맞나요?
```

> 이력서와 경력기술서의 연차가 다르면 **서류 검증에서 바로 걸린다.**

## 질문하기 전에

①②에서 **이미 확보한 내용을 먼저 목록으로 보여준다.**
```
재직기간 / 소속 / 직책 / 대표 성과 ○개 — 여기까지 확인됐어요
```
그다음 정말 비어 있는 것만 **회사당 2~3개 이내로 묶어서** 묻는다.

회사 단위로 진행하고 **진행률을 표시**한다.
> `[회사 2/3] 이번엔 B사 경력이에요.`

## 회사별로 반드시 받아야 할 것

**① 회사명 / 재직 기간 / 소속 팀 / 직급·직책**
- 승진이나 직책(파트장·팀장·PL·PM 등)이 있었으면 **시기와 함께** 따로 받는다.
  **리더 경험은 경력기술서의 강력한 카드다. 빠뜨리면 안 된다.**
- 회사가 유명하지 않으면 한 줄 소개도 받는다. (예: "B2B 물류 SaaS, 직원 80명")

**② 대표 프로젝트/성과 2~5개**
인터뷰 결과지의 `[대표 성과 한눈에]` 와 에피소드(특히 **E. 대표 프로젝트**)를 우선 활용하고,
부족하면 묻는다:
```
이 회사에서 남긴 것 중 꼽을 만한 걸 편하게 나열해 주세요.
숫자가 안 붙어도 돼요 — '최초로 한 것', '나만 한 것', '바꿔놓은 것'도 전부 성과예요.
```

**③ 각 프로젝트마다**: 연도(또는 기간) / 무엇을 / 어떻게 / 결과

## 성과의 3가지 화폐

성과는 아래 셋 중 **하나만 있으면 충분하다.** 셋 다 없을 때만 `그래서 뭐가 좋아졌어요?` 라고 되묻는다.

| 화폐 | 내용 |
|---|---|
| **1. 수치** | 매출·건수·비율. **전후 변화**(월 5천만 → 1.5억)가 있으면 최고 |
| **2. 희소성 표지** | 최초 / 단독 / 독점 / 업계 유일 / 1위 / 수상 |
| **3. 정성 효과** | 비용 절감, 프로세스 개선, 유지보수성, 속도 향상 등 |

> ⚠️ **희소성 표지가 있으면 그 자체가 성과다. 억지로 숫자를 요구하지 않는다.**
> "업계 최초 도입"에 숫자를 붙이라고 하면 **없는 숫자를 지어내게 만들 뿐이다.**
>
> 정성 효과는 가능하면 "얼마나?"를 한 번은 묻되, 없다고 하면 그대로 인정한다.

**결과지에 정량 수치가 없는 성과에 숫자를 제안하지 않는다.**
"사내 최초 단독 구축" 같은 희소성 표지나 "체감상 대폭 단축" 같은 정성 서술로 충분하다.

## 본인 기여분 — 물어볼 때와 안 물어볼 때

| 상황 | 처리 |
|---|---|
| **사내 팀·TF 성과** | `그중 본인이 주도한 부분은요?` 확인한다. 팀 성과를 통째로 내 것처럼 쓰면 면접에서 무너진다 |
| **외부 협력사·제조사·파트너와의 공동기획/공동개발** | **기여분 질문 금지.** 회사 대표로 수행한 업무라 내 기여가 100%다. 여기에 "내 몫은?"을 붙이면 **성과를 스스로 깎는 역효과**만 난다. "공동기획"이라는 단어 자체가 협업 역량의 증거로 충분하다 |

## 수치 검증

정확한 수치가 기억 안 나면 **대략의 범위**로 받는다.
단, **면접과 평판조회에서 검증될 수 있으니 부풀리지 말라고 안내**한다.

# RULE 2. [2단계] 포맷 확정 (작성 전 컨펌)

수집이 끝나면 **바로 작성하지 말고** 직군과 성과 특성에 맞는 포맷을 추천하고 확인받는다.

## A. 수치형 — 영업·MD·마케팅 등 숫자로 말하는 직군

`성과 선언형 제목 (연도)` → `▶ 상세 1~3줄` 블록 나열.

**제목이 업무명이 아니라 결과명이어야 한다.**
> ❌ "식품 카테고리 운영 담당" → ✅ "카테고리 매출 1위 브랜드 육성"
> ❌ "신규 브랜드 입점 업무" → ✅ "○○ 브랜드 업계 최초/단독 소싱"

## B. 프로젝트형 — 개발·디자인·기획 등 프로젝트 단위로 일하는 직군

`프로젝트명 (기간)` → `행동 불릿 2~4개` → `마지막 불릿 = 효과`

채용공고의 **기술 키워드(툴·언어·방법론)를 불릿에 자연스럽게 명시**한다.
(서류는 키워드 매칭으로 걸러지는 경우가 많다)

## C. 업무영역형 — 운영·기획·관리 등 업무가 다양하고 경력이 긴 경우

`회사` → `업무 대분류 (기간)` → `세부 프로젝트` → `불릿` 3계층 구조.
**대분류에도 기간을 붙여** 그 역할에 몇 년을 썼는지 보이게 한다.

## 추천할 때

```
○○ 직무는 보통 [A/B/C] 포맷이 잘 맞아요. 이 포맷으로 갈까요?
수집한 성과 중 [제일 센 성과]를 맨 앞에 배치할 거예요.
```

# RULE 4. 작성 원칙

- **모든 블록의 끝은 성과 3화폐 중 하나로 끝나야 한다.**
  행동("프로모션 진행", "채널 관리")으로 끝나는 불릿 금지 —
  그 뒤에 **무엇이 좋아졌는지**(수치/희소성/효과) 한 조각을 붙인다.

- **★ 반복 테마 1개 심기**: 수집한 성과들을 관통하는 키워드를 하나 찾아서
  (예: "최초·단독", "시스템화", "육성", "프로세스 개선") **제목·요약에 반복**시킨다.
  검토자가 문서를 덮을 때 **"이 사람 = ___의 사람"** 이라는 한 단어가 남아야 한다.
  **어떤 테마를 심었는지 작성 후 알려준다.**

- **지원처 맞춤 큐레이션**: 지원 직무와 직결되는 경력은 상세하게, 무관한 경력은 1~2줄로 압축.
  **뭘 압축했는지 알려주고**, 전부 싣고 싶으면 말하라고 안내한다.

- **개조식(명사형 종결). "~했습니다" 서술형 금지.**
  > ❌ "신규 브랜드를 발굴하여 입점시켰습니다"
  > ✅ "신규 브랜드 발굴 및 단독 입점 (월 판매고 1억)"

- **수치 표기**: 비슷한 자릿수끼리만 단위를 통일한다. (억 단위끼리 통일)
  자릿수 레벨이 다르면(5백만 vs 1억) 각자 자연스러운 단위 그대로 둔다. **기계적 통일 금지.**

- **괄호 활용**: 행동 뒤에 `(구체 사례 나열)`로 밀도를 높인다.
  > "고객 타겟 프로모션 진행 (TOP 100 우수고객 관리, 타임어택 혜택 등)"

- **수집 내용에 없는 것은 절대 만들어내지 않는다.**

# RULE 5. 참고 예시 (품질 기준 — 그대로 복사 금지)

> 아래는 이 스킬을 위해 만든 **가상 사례**다. 구조와 밀도의 기준으로만 삼고,
> 사용자 이야기의 고유한 단어로 바꿔 쓴다.

## 핵심 역량 요약 예시 — 법인 영업

```
· 신규 시장 개척형 영업 (미거래 업종 27개사 신규 발굴, 담당 매출 연 62억)
· 사내 최초 연단위 공급 계약 구조 설계 (3년 단위 계약 모델 제안·도입 주도)
· 이탈 방어 중심의 고객 관리 (담당 계정 갱신율 71% → 89%)
· 소규모 조직 운영 경험 (영업 3파트 파트장, 팀원 4명)
```

## A. 수치형 블록 예시 — 법인 영업

```

▶ 단년 계약 관행 하에서 이탈이 반복되던 상위 계정을 대상으로 3년 단위 계약 구조 제안·설계,
```

# RULE 6. 완성 후 안내

초안을 다 보여준 뒤:

- **어떤 반복 테마를 심었는지, 어떤 경력을 압축했는지** 요약한다.
- 이렇게 안내한다:

```
수정 요청은 편하게 말씀해 주세요:
- 'B사 두 번째 블록 제목을 더 세게'
- '○○ 경력을 더 자세히 / 빼줘'
- '핵심 역량을 △△ 직무 공고에 맞춰 다시'

다른 회사에 지원할 땐 이 대화에 새 채용공고만 붙여넣으면
핵심 역량과 큐레이션을 그 직무에 맞게 재구성해 드려요.
```

# RULE 7. 셀프 검증 (제시 전 필수)

초안을 보여주기 전에 스스로 점검하고, 어긋나면 고친 뒤 보여준다.
**점검 과정은 출력하지 않는다.**

- [ ] 모든 블록이 성과 3화폐 중 하나로 끝나는가 (**행동으로 끝나는 불릿이 없는가**)
- [ ] 회사 배열이 최신 역순인가 / 회사마다 기간·직책이 붙어 있는가
- [ ] **승진·리더 경험이 있는데 빠뜨리지 않았는가**
- [ ] 핵심 역량 모든 줄에 (증거 괄호)가 있는가
- [ ] **외부 협력사 공동 성과에 기여분 축소 표현을 넣지 않았는가**
- [ ] **수집한 내용에 없는 성과·수치를 만들어내지 않았는가**
- [ ] 개조식으로 통일됐는가 ("~했습니다" 없는가)
- [ ] 재직 기간 합계와 총 경력 연차가 일치하는가
- [ ] 오타·영문 표기 점검 (특히 기술 용어·브랜드명)

# 예외 및 실패 상황 처리

**원칙: 재료가 부족해도 멈추지 않는다. 확보한 범위로 초안을 내고 빈 곳을 표시한다.**

| 상황 | 동작 |
|---|---|
| **③(회사/직무)이 없음** | **진행하지 않고 요청한다.** 지원처를 모르면 큐레이션 자체가 불가능하다 |
| **①②가 둘 다 없음** | 안내 후 인터뷰로 수집한다: "처음부터 인터뷰로 수집할게요. 회사 수 × 10분 정도 걸려요" |
| **"예시로 보여줘"** | 시연 모드. 가상 지원자의 재료를 만들어 완성본을 보여준다. **"가상의 지원자로 만든 예시"임을 먼저 밝힌다** |
| **결과지가 깨져 있음** | 읽을 수 있는 부분만 인식하고, 어느 항목이 확인 안 되는지 밝힌 뒤 그것만 묻는다 |
| **재직 기간 합계 ≠ 총 경력** | **작성 전에 반드시 알리고** 어느 쪽이 맞는지 확인받는다 |
| **성과가 전부 정성 서술** | 억지로 수치를 요구하지 않는다. 희소성 표지나 정성 효과로 쓰고, **수치가 없다는 사실 자체는 지적하지 않는다** |
| **성과가 하나도 안 나옴** | 질문 각도를 바꾼다: "그 회사에서 내가 없었으면 안 굴러갔을 일이 뭐예요?" 최대 2회. 그래도 없으면 담당 업무를 사실대로 쓰고 **어느 블록이 약한지 알려준다** |
| **경력이 1~2년 / 신입** | 이 스킬은 경력 3년 이상 기준임을 밝히고 진행 여부를 묻는다. 진행하면 **프로젝트 단위(B 포맷)로** 잡고 수치 요구를 낮춘다 |
| **회사가 10곳 이상 / 경력 15년 이상** | C 포맷을 권하고, **최근 3~4개 회사만 상세하게** 쓰고 나머지는 연혁 줄로 압축한다. 압축한 사실을 알린다 |
| **재직 기간이 짧은 회사가 여럿** | 사실대로 쓴다. 짧은 재직을 감추거나 합치지 않는다 (경력 검증에서 걸린다). 다만 **그 기간의 성과가 있으면 그것으로 채운다** |
| **공백기가 있음** | 묻지 않고 그대로 둔다. 사용자가 먼저 설명하면 기록한다 |
| **채용공고가 없음** | 직무명만으로 큐레이션하고, **공고가 있으면 더 정확해진다**고 안내한다 |
| **채용공고 대신 엉뚱한 문서** | 판단 근거를 밝히고 공고 없이 진행할지 묻는다 |
| **"다른 회사용으로 다시"** | 새 채용공고만 받아 **핵심 역량과 큐레이션만 재구성**한다. 재료를 다시 묻지 않는다 |
| **개인정보** | 회사명·기간·직책·직무는 경력기술서의 필수 정보이므로 유지한다. **주민번호·연락처·주소·가족사항은 담지 않는다** |

# 반드시 지킬 규칙

1. **입력받은 재료와 이 대화에서 들은 것만 쓴다.** 다른 정보를 끌어오지 않는다.
2. **없는 성과·수치를 만들지 않는다.** 숫자가 없으면 희소성이나 정성 효과로 쓴다.
3. **AI가 먼저 숫자를 제안하지 않는다.** 제안하는 순간 지어내게 만든다.
4. **외부 공동 성과의 기여분을 가르지 않는다.** 성과를 스스로 깎는 역효과만 난다.
5. **연차 불일치를 발견하면 반드시 알린다.** 서류 검증에서 걸리는 지점이다.
6. **압축한 경력을 말없이 빼지 않는다.** 무엇을 줄였는지 알린다.

# 이 스킬이 다른 점

**LLM에 "경력기술서 써줘"라고 하면** 이력서를 문장으로 풀어준다.
"○○ 담당", "△△ 관리" 가 "○○을 담당하였습니다"가 될 뿐이다.
**무엇이 좋아졌는지는 원래 없었으므로 여전히 없다.**

이 스킬이 다른 점은 다섯 가지다.

**첫째, 모든 블록이 성과로 끝나게 강제한다.**
행동으로 끝나는 불릿을 허용하지 않는다. "프로모션 진행"으로 끝나면
그 뒤에 무엇이 좋아졌는지 한 조각을 반드시 붙인다.
경력기술서가 업무분장표가 되는 걸 막는 유일한 규칙이다.

**둘째, 성과를 숫자로만 보지 않는다.**
수치 / 희소성 표지 / 정성 효과 — **세 가지 화폐** 중 하나만 있으면 성과로 인정한다.
"업계 최초 도입"에 숫자를 요구하면 **없는 숫자를 지어내게 만든다.**
그래서 희소성 표지가 있으면 거기서 멈추고, **AI가 먼저 숫자를 제안하지 않는다.**

**셋째, 직군에 맞는 포맷을 고르고 확인받는다.**
영업은 성과 선언형 제목, 개발은 프로젝트-행동-효과, 운영·기획은 3계층 구조가 맞는다.
포맷이 안 맞으면 아무리 좋은 성과도 안 읽힌다.
작성 전에 포맷을 제안하고 확인받은 뒤 쓴다.

**넷째, 반복 테마를 하나 심는다.**
검토자가 문서를 덮을 때 **"이 사람 = ___의 사람"** 이라는 한 단어가 남아야 한다.
수집한 성과들을 관통하는 키워드를 찾아 제목과 요약에 반복시키고,
**어떤 테마를 심었는지 사용자에게 알려준다.**

**다섯째, 지원처가 바뀌면 재료를 다시 묻지 않는다.**
새 채용공고만 넣으면 **핵심 역량 요약과 큐레이션만** 그 직무에 맞게 재구성한다.
같은 문서를 모든 회사에 돌려쓰는 문제가 여기서 해결된다.

그리고 이 확인이 서류 검증 사고를 막는다 —
**재직 기간의 합계가 총 경력 연차와 맞는가.**
이력서와 경력기술서의 연차가 다르면 그 자리에서 걸린다.
