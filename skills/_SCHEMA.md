# 공통 스킬 레코드 스키마 (v1)

3개 스킬이 공유하는 데이터 형식. 이게 고정되어야 추출 결과를 매칭 스킬에 그대로 넘길 수 있다.

## 스킬 카테고리 (6종)

| 코드 | 이름 | 설명 | 예 |
|---|---|---|---|
| `TECH` | 기술·도구 | 특정 기술, 언어, 툴, 플랫폼 | Python, Figma, SAP, 용접기 |
| `DOMAIN` | 도메인 지식 | 업종·분야 이해 | 이커머스 물류, 임상시험, 세무 |
| `TASK` | 직무수행능력 | 실제 수행하는 업무 단위 | 재무제표 작성, A/B 테스트 설계 |
| `SOFT` | 대인·태도 역량 | 협업, 커뮤니케이션, 리더십 | 이해관계자 조율, 팀 리딩 |
| `CERT` | 자격·학력·어학 | 검증 가능한 증명 | 정보처리기사, TOEIC 900 |
| `COND` | 정량 조건 | 연차, 근무형태 등 | 경력 3년 이상, 야간근무 가능 |

## 숙련도 레벨 (1~5)

| 레벨 | 이름 | 판정 기준 |
|---|---|---|
| 1 | 노출 | 학습·교육 이수 수준. 실무 적용 근거 없음 |
| 2 | 보조 | 지도·리뷰 하에 수행. 부분 참여 |
| 3 | 독립 | 혼자 처음부터 끝까지 수행 가능 |
| 4 | 개선 | 기존 방식을 개선·최적화하거나 문제를 해결한 근거 있음 |
| 5 | 주도 | 설계·표준화하거나 타인을 지도한 근거 있음 |

## 스킬 레코드 필드

```json
{
  "name": "정규화된 스킬명",
  "raw": "원문에 쓰인 표현 그대로",
  "category": "TECH | DOMAIN | TASK | SOFT | CERT | COND",
  "level": 1,
  "level_basis": "이 레벨로 판정한 근거 한 줄",
  "evidence": "원문에서 그대로 인용한 문장",
  "confidence": "high | medium | low"
}
```

- `evidence`는 **원문 그대로 인용**. 요약·의역 금지. 추론이면 `confidence: low`.
- `name`은 표기 흔들림을 정규화한다. `파이썬`/`Python3`/`python` → `Python`

## 이력서 추출 결과의 추가 필드

```json
{ "years": 3.5, "recency": "current | recent | past", "source_section": "경력 > OO회사" }
```

- `recency`: `current`(현재도 사용) / `recent`(3년 이내) / `past`(3년 초과)

## 채용공고 추출 결과의 추가 필드

```json
{ "requirement": "must | nice | implicit", "priority": 1 }
```

- `requirement`: `must`(자격요건·필수) / `nice`(우대사항) / `implicit`(명시 안 됐지만 업무내용상 필요)
- `priority`: 공고 내 강조도 1(최상)~3(낮음)
