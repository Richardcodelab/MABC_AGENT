# 구글 폼 제출 답안 (최종 — 타임리 제작본 기준)

> 타임리에서 제작한 `jobseeker-coverletter-coach` 기준으로 작성.
> `docs/04-submission-text.md`는 원고 기준이므로 **사용하지 않는다.**

## ⚠️ 먼저 정할 것 — 스킬명

폼은 **스토어에 올린 이름과 100% 동일**할 것을 요구한다.
스킬 문서의 H1이 `자소서 작성 코칭 스킬`이므로, **스토어에도 이 이름으로 올린다.**

더 눈에 띄는 이름을 쓰고 싶으면 바꿔도 되지만,
**스킬 문서 H1 · 스토어 · 폼 세 곳을 모두 같게** 맞춰야 한다.

## 스킬명
```
자소서 작성 코칭 스킬
```

## 스킬 1줄 요약 (50자 이내)
```
문항이 묻는 축을 뽑고 짧은 인터뷰로 소재를 캐서 자소서 초안까지 씁니다
```
(40자)

## (문제 정의) 이 스킬은 어떤 문제를 해결하나요?
```
[누가] 이직을 준비하는 경력 3년 이상 지원자입니다.

[얼마나 자주] 지원 시즌에 5~10개 회사에 지원하고, 회사마다 자소서 문항이 3~5개입니다.

[어떤 작업에] 문항을 읽고, 어떤 경험을 쓸지 고르고, 그 경험을 문항에 맞게 재구성하고,
분량을 맞추는 작업입니다.

[시간은 얼마나] 문항 하나에 1~2시간, 회사 한 곳에 5~10시간이 들어갑니다.
그런데 그 시간의 절반 이상이 "무슨 이야기를 쓸지 정하는" 단계에서 사라집니다.
(경력 이직자 체감 기준 추정치입니다)

[무엇이 문제인가] 실패하는 방식이 세 가지입니다.

첫째, 경험이 없는 게 아니라 꺼내지 못합니다.
"지원동기를 쓰세요"에는 아무것도 안 떠오르다가,
"정보가 부족한 상태에서 결정해야 했던 순간이 있어요?"라고 물으면 장면이 나옵니다.
그런데 혼자서는 자기한테 이런 각도로 묻지 못합니다.

둘째, 문항을 안 읽고 답합니다.
문항은 "판단이 필요했던 순간"을 물었는데 답은 "열심히 한 경험"이 옵니다.
자기가 아는 제일 좋은 이야기부터 꺼내니까 스스로 잡아내지 못합니다.

셋째, 회사 자리에 아무 말이나 넣습니다.
"업계를 선도하는 귀사에서" 같은 문장은 근거를 물으면 답할 수 없습니다.

세 가지는 원인이 다르지만 구조적으로 같은 한 지점에서 걸립니다.
자기 경험을 바깥에서 바라보는 장치, 즉 질문의 각도를 바꿔주는 상대가 없다는 것입니다.
혼자서는 자기한테만 통하는 언어로 기억을 검색하니까,
질문이 조금만 달라져도 인덱싱이 되지 않습니다.
```

## (문제 해결 방식) 그 문제를 어떻게 해결하나요?
```
[해결 방식]
글을 대신 써주지 않습니다. 지원자가 자기 경험을 문항의 구조에 맞게 꺼내도록 돕습니다.

1. 문항이 실제로 검증하려는 축을 먼저 뽑습니다.
   판단(정보가 부족할 때 뭘 근거로 결정하는가), 회복(막혔을 때 어떻게 다시 움직이는가),
   관계(이해가 부딪히면 어떻게 푸는가), 지속(이 자리를 계속할 이유가 있는가) 네 가지입니다.
   축 아래에 요소를 1~4개 뽑는데, 이 요소가 인터뷰에서 캘 단위가 됩니다.
   "지원동기와 입사 후 포부"는 축이 지속이고 요소가 네 개
   (왜 이 직무 / 왜 이 회사 / 왜 지금 / 입사 후)입니다.

2. 그 축에 필요한 것만 짧게 캡니다.
   문항 단위가 아니라 축 단위로 캐기 때문에,
   문항 3개가 판단·판단·관계면 캘 것은 두 개입니다.
   문항 3개 기준 10~15분입니다.

3. 캐는 깊이는 시간이 아니라 요소가 정합니다.
   요소마다 최소 신호를 정해두고, 세 개 중 두 개가 들어오면 확보로 봅니다.
   예를 들어 "판단의 근거"는 무엇이 부족했는지 / 무엇을 보고 판단했는지 /
   왜 그쪽을 골랐는지 중 두 가지가 나오면 확보입니다.
   채워지면 멈추고, 안 채워지면 계속 팝니다.

4. 캔 재료만으로 초안을 씁니다.
   주장 - 장면 - 전환 - 잔상 네 박자로 쓰며, 초안 단계에서 새 소재를 넣지 않습니다.

5. 보여주기 전에 다섯 가지를 스스로 점검합니다.

[유사 스킬 및 차별점]
자소서 작성 스킬은 이미 여럿 있습니다. 차이는 여섯 가지입니다.

첫째, 쓰기 전에 묻습니다.
대부분의 자소서 스킬은 요청을 받으면 바로 완성된 글을 냅니다.
문장은 매끄럽지만 그 글에는 지원자가 없습니다.
이 스킬은 인터뷰를 먼저 합니다.
지원자에게 경험이 없는 게 아니라 꺼내지 못하는 것이기 때문입니다.

둘째, 문항을 해부해서 필요한 축만 캡니다.
"판단이 필요했던 순간"에 회복 이야기를 넣으면 아무리 좋은 이야기여도 동문서답입니다.
축을 먼저 정하기 때문에 이 실패가 구조적으로 막히고,
필요한 축만 캐기 때문에 인터뷰가 짧게 끝납니다.

셋째, 꼬리질문이 준비된 다음 항목으로 건너뛰지 않습니다.
AI는 답을 받으면 자기가 정한 다음 질문으로 넘어가기 쉽습니다.
그러면 첫 답변만 모이는데, 자소서에 쓸 수 있는 문장은 그다음 답변에서 나옵니다.
이 스킬은 직전 답변에 나온 단어·수치·이유·사람·결정 중 하나에서 다음 질문을 만듭니다.
"배송 가능 세대가 38% 늘었어요"에서 멈추지 않고
"원래 몇 %였는데요 - 평균 대비 좋은 수치예요 - 매출에는 어느 정도 기여했어요"로 이어갑니다.

넷째, 확보 여부를 최소 신호로 판정합니다.
"확보된 것 같은 느낌"으로 진행하면 실행할 때마다 결과가 달라집니다.
축별 요소마다 최소 신호를 정해두고 세 개 중 두 개 규칙으로 판정하기 때문에,
같은 입력에 같은 방식으로 동작하고 미확보도 모호하게 남지 않습니다.

다섯째, 초안 단계에서 새 소재를 넣지 않습니다.
AI는 문장을 만들면서 그럴듯한 내용을 덧붙이기 쉽습니다.
이 스킬은 인터뷰로 캔 재료 안에서만 문장화하므로,
사용자가 면접에서 답할 수 없는 내용이 섞이지 않습니다.

여섯째, 캔 재료가 카드로 남습니다.
다음 회사에 지원할 때 소재 카드를 다시 넣으면 이미 캔 축은 건너뜁니다.
지원 시즌이 길어질수록 누적 효과가 생깁니다.

그리고 마지막에 초안 그대로 제출하지 말라고 스스로 말합니다.
최종 문장은 본인이 확인하고 다듬어야 한다는 점을 분명히 합니다.
```

## (스킬 동작 방식) 어떤 순서로 동작하나요?
```
[입력]
자소서 문항 목록(필수), 문항별 글자수, 지난번 소재 카드(있으면),
회사·직무 정보(아는 만큼).
문항 외에는 비어 있어도 진행합니다. 없는 것은 "근거 미확보"로 표시합니다.

실행 모드는 세 가지이며 첫 메시지를 보고 판단합니다.
· 작성 모드 — 기본. 문항 세트를 받아 전체 단계를 진행합니다.
· 이어쓰기 모드 — 소재 카드를 붙여넣으면 그 지점부터 이어갑니다.
· 시연 모드 — "예시로 보여줘"라고 하면 가상 지원자로 전체 흐름을 한 번에 보여줍니다.
  이 스킬은 인터뷰형이라 질문에 답하지 않으면 결과물을 볼 수 없기 때문입니다.

[처리]
A. 문항 해부 — 문항 전체를 한 번에 읽고 축과 요소를 뽑습니다.
   4축에 안 맞는 문항은 억지로 끼우지 않고, 가장 가까운 축과
   "그 축으로는 덜 맞는 이유"를 함께 보여주고 확인받습니다.
   성장 문항은 축을 4개 중에서 고르고 요소는 성장류 요소를 씁니다.

B. 재료 점검 — 뽑은 축 전체에 대해 있음/없음/각도 안 맞음을 빠르게 가릅니다.
   캐기 여부를 결정하는 게이트이며, 이미 있는 것은 다시 묻지 않습니다.

C. 캐기 — 축 단위로 진행합니다.
   여는 질문으로 장면을 꺼낸 뒤, 요소가 채워질 때까지 꼬리질문을 이어갑니다.
   꼬리질문은 구체화 / 대비 / 이유 / 수치·범위 / 결과·이후 다섯 가지 방향으로 던집니다.
   한 번에 하나만 묻고, 빈칸 채우기와 매 턴 요약 확인은 하지 않습니다.
   감정 추정("힘들었겠어요?")이나 끼워 맞추기로 유도하지 않습니다.
   사내 팀 성과는 본인 몫을 확인하고,
   외부 협력사와의 공동 작업은 기여분을 억지로 가르지 않습니다.
   축 하나가 끝나면 소재 카드를 보여주고 확인받습니다.

D. 배치와 각도 — 문항 세트를 함께 보고 어느 경험을 어느 문항에 놓을지 정합니다.
   같은 경험의 재사용은 축이 다를 때 두 번까지로 제한합니다.
   왜 그 조합인지 근거를 붙여 확인받은 뒤 작성으로 넘어갑니다.

E. 초안 — 캔 재료만으로 네 박자로 씁니다.
   주장(한 문장 선언) - 장면(겪은 일) - 전환(첫 시도가 안 됐고 뭘 다르게 했는지)
   - 잔상(결과와 인과).
   분량은 목표 글자수 ÷ 65로 목표 문장 수를 계산합니다.
   AI가 한글 글자수를 정확히 세지 못하기 때문입니다.

F. 자가 검증 — 다섯 가지를 스스로 점검하고 어긋나면 고친 뒤 보여줍니다.
   문항이 묻는 것에 답했는가 / 요소가 빠지지 않았는가 /
   회사 부분에 근거를 댈 수 있는가 / 본인이 한 건 어디까지인가 /
   첫 시도부터 잘된 이야기는 아닌가.

G. 인계 — 소재 카드에 재사용 태그를 붙여 전달하고,
   초안 그대로 제출하지 말라고 안내합니다.

[출력]
① 문항 해부 결과 (축 / 요소 / 목표 문장 수)
② 소재 카드 (축별, 요소 확보 상태와 본인 몫 구분 포함)
③ 배치표 (어느 경험을 어느 문항에 어떤 각도로)
④ 문항별 초안 + (문장 ○개 / 목표 ○개)
⑤ 인계 카드 (재사용 태그 포함)
⑥ 제출 전 확인 안내

[예외 처리]
원칙은 세 단계입니다. 이상 상황을 짧게 짚고, 가능한 만큼 정리하고,
못 한 부분은 사유를 남기고 그냥 넘기지 말고 선택지를 줍니다.
"입력이 잘못되었습니다"만 출력하고 끝내지 않습니다.

입력 문제 — 빈 입력, 문항 없이 경험만 보냄, 이력서를 문항으로 넣음,
한 문항이 두 가지를 물음, 4축에 안 맞는 문항.
인터뷰 중단 — 딴 걸 물음, 답이 계속 막연함, "그 축은 경험이 없다",
요소를 하나도 못 채움.
요구 문제 — "그냥 알아서 써줘", "경험 없는데 만들어줘",
회사에 대한 근거 없는 칭찬 요구, 전 직장 비방 요구, 수치 부풀림.
기타 — 문항 수가 경험보다 많음, 회사 정보를 전혀 모름, 신입 사용, 개인정보.

전제와 충돌하는 요구에는 톤 원칙 네 가지를 적용합니다.
사용자를 탓하지 않고 사용자 이익으로 설명하고, 거절만 하지 않고 대안을 붙이되
그 대안에 "새로 만들지 않는다"는 선을 함께 박고,
한 번만 설명하고 반복하지 않습니다.
옳은 말을 반복하면 사용자가 스킬을 닫아버리기 때문입니다.

[사용하지 않는 것이 좋은 경우]
· 이미 쓴 자소서의 첨삭 — 이 스킬은 백지에서 인터뷰로 시작하는 구조입니다.
  초안이 있으면 그 초안에 갇혀 잘못 고른 소재를 계속 다듬게 됩니다.
· 경험을 지어내 채우기 — 답한 내용만으로 쓰며, 없으면 비워둡니다.
· 합격 여부 예측 — 서류상 소재 정리만 하며 채용 결과를 예측하지 않습니다.
```

## 최종 확인
- [ ] 스킬명이 스토어 · 폼 · 문서 H1 세 곳에서 동일한가
- [ ] 1줄 요약이 50자 이내인가 (현재 40자)
- [ ] 스토어 업로드 시 태그 **`mabc-final`**

- [ ] (팀) 실제 업로드한 팀원의 계정 이메일을 기재했는가
- [ ] API Key 엑셀은 **첨부하지 않는다** (외부 API 미사용)
- [ ] 체크리스트 항목에 전부 체크했는가
