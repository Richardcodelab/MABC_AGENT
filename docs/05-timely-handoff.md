# 타임리 이관 및 제출 절차

> 이 저장소의 `SKILL.md`는 **원고**다. 실제 제작은 타임리에서 Solar Pro 4로 한다.

## 🚨 가장 먼저 — 왜 타임리에서 만들어야 하는가

**규정 제5조 1항**: *"제출물은 타임리 서비스 내 지정한 MABC 워크스페이스에서 제작한 결과물을
이야기한다. **타 서비스를 통해 만든 skill은 실격처리 한다.**"*

→ 이 저장소의 마크다운을 로컬에서 zip으로 압축해 제출하면 **실격**이다.
→ 반드시 타임리 편집창에 옮겨 붙여 **거기서 제작·테스트**하고, **[내려받기]한 `skill.zip`** 을 낸다.

## 1. 환경 준비

| 항목 | 확인 |
|---|---|
| 로그인 계정 | 대회 사전 신청 시 제출한 **이메일과 동일**해야 함 |
| 스페이스 | 좌측 상단에서 **`Making AI Beneficial Challenge`** 로 전환 (필수) |
| 모델 | **Solar Pro 4** (타 모델 사용 시 실격, fallback 예외) |
| 크레딧 | 우측 상단 프로필에서 **20,000** 잔액 확인 |

> 크레딧이 안 보이거나 결제 팝업이 뜨면 위 세 가지를 먼저 확인한다.
> 팀원도 **각자 개별 참가 신청**을 해야 개별 계정에 크레딧이 들어온다 (신청 시 동일 팀명 기재).

## 2. 이관 순서

**대표작인 `지원 판단 리포트`부터 만든다.** 최고점 1개만 반영되므로 가장 공들일 것부터.

1. `skills/skill-matcher/SKILL.md` → 타임리 스킬 편집창
2. `skills/jd-skill-extractor/SKILL.md`
3. `skills/resume-skill-extractor/SKILL.md`

### 이관 시 조정할 것

타임리의 입력 폼 구조에 따라 잘라 넣어야 할 수 있다. 우선순위는 이렇다:

| 우선순위 | 섹션 | 이유 |
|---|---|---|
| 1 | **예외 및 실패 상황 처리** | 설계 체계성 30점의 핵심 심사 질문 |
| 2 | **처리 절차의 판정 기준 표** | 재현 가능성 20점 (레벨 판정, 대응 판정) |
| 3 | **출력 형식** | 설계 체계성 (출력 구조) |
| 4 | **이 스킬이 푸는 문제** | 문제정의 30점 |
| 5 | **이 스킬이 다른 점** | 독창성 20점 |
| 6 | 반드시 지킬 규칙 | 위 항목들에 분산 반영 가능 |

**길이 제한에 걸리면 1~5는 유지하고 6을 줄인다.** 1~5는 각각 배점 항목과 직결된다.

> `description` 프론트매터는 스토어에서 검색·노출될 때 쓰이므로 **무엇을 언제 쓰는지**가
> 드러나게 유지한다.

## 3. 테스트

`samples/TEST-PLAN.md`의 케이스를 **각각 새 대화창에서** 실행한다.
심사가 새 대화창 + 처음 보는 입력으로 이뤄지기 때문이다.

권장 순서:
1. 정상 케이스 (A1, B1, C1)
2. 핵심 차별점 (A2, B1, C2) — 안 되면 독창성 점수가 안 나온다
3. 예외 케이스 전부 — **배점의 절반이 여기 걸려 있다**
4. 재현성 (A7, B8, C13) — 같은 입력 2회 실행

> 테스트도 크레딧을 쓴다. 20,000 안에서 계획적으로 돌린다.

## 4. 제출 (3-Step)

### Step 1 — 스토어 업로드
1. 스킬 편집창에서 **[내려받기]** → `skill.zip` 저장
2. 우측 상단 **[스토어에 올리기]**
3. 태그 입력란에 **`mabc-final`** ← 누락 시 자동 스크리닝에서 빠질 수 있음

### Step 2 — 구글 폼
1. MABC 2026 예선 과제 제출 폼 접속
2. 대회 신청 이메일, 타임리 계정, **스킬명 / 1줄 요약 / 상세 설명** 작성
   → `docs/04-submission-text.md`에 준비되어 있음
3. `skill.zip`을 **파일명 그대로** 첨부
4. (팀) **실제 업로드한 팀원의 계정 이메일**을 정확히 기재

> 스킬 1개당 폼 1회. 스토어만 올리고 폼을 안 쓰면 평가 대상 제외.

### Step 3 — 확인
- 스토어 **[내가 올린]** 탭에서 `승인 대기` 또는 게시 상태
- 구글 폼 제출 완료 메시지 + 작성 사본 이메일

## 5. 최종 체크리스트

- [ ] 스페이스가 `Making AI Beneficial Challenge`인가
- [ ] 모델이 **Solar Pro 4**인가
- [ ] 스토어 태그 **`mabc-final`** 을 넣었는가
- [ ] (팀) 폼에 실제 업로드 계정 이메일을 기재했는가
- [ ] **새 대화창에서 처음 보는 입력**으로 정상 동작하는가
- [ ] `skill.zip`을 폼에 첨부했는가 (파일명 그대로)
- [ ] `SKILL.md`에 인증키·비밀번호·실명이 없는가
- [ ] 예시에 실제 채용공고 원문을 쓰지 않았는가 (저작권)
- [ ] 외부 API를 쓰지 않았는가 (쓴다면 Key 엑셀 첨부 + 동의 체크)
