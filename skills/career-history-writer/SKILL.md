# 경력기술서 작성기 (경력자용)

경력기술서는 **자서전이 아니라 증거 목록**이다.
검토자는 이 문서를 읽지 않는다. **훑는다.** 30초 안에 "이 사람이 뭘 할 수 있는가"를 판단한다.

그런데 지원자는 **"내가 무엇을 했는가"** 를 쓴다. 그 간극이 이 문서가 실패하는 지점이다.

여섯 단계로 진행한다.

```
1. 훑기  →  2. 캐기(인터뷰)  →  3. 등급  →  4. 진열  →  5. 초안  →  6. 30초 테스트
```

## 이 스킬이 푸는 문제

**[누가]** 이직을 준비하는 3년 이상 경력 지원자.

**[얼마나 자주]** 이직 시즌에 5~10개 회사에 지원한다. 대부분 경력기술서를 **한 번 써두고 돌려쓴다.**

**[어떤 작업에]** 회사별 재직 기간·직책을 정리하고, 프로젝트를 떠올리고, 성과를 문장으로 만드는 작업.
경력 5년이면 회사 2~3곳에 프로젝트가 10개 이상이다.

**[시간은 얼마나]** 처음 한 번 쓰는 데 **4~8시간**. 지원처마다 고쳐야 하는데 시간이 없어 **그대로 낸다.**
(경력 이직자 체감 기준 추정치)

**[무엇이 문제인가]** 원인은 문장력이 아니라 **질문을 잘못 던진 것**이다.

혼자 쓸 때 스스로에게 던지는 질문은 **"내가 뭘 했지?"** 다.
그 질문의 답은 업무 목록이다 — "카테고리 운영 담당", "채널 관리", "신규 입점 업무".
무엇을 **했는지**는 있는데 무엇이 **남았는지**가 없다. 경력기술서가 업무분장표가 된다.

던져야 할 질문은 따로 있다.

> **"내가 없었으면 안 굴러갔을 일이 뭐였지?"**
> **"내가 떠난 뒤에도 계속 쓰이는 게 뭐지?"**

이 질문에는 업무 목록이 아니라 **증거**가 나온다.
그런데 혼자서는 이 각도로 자기에게 묻지 못한다. 그래서 이 스킬은 **인터뷰로 캔다.**

# 입력

```
① 회사명 / 지원 직무:            ← 필수
② 채용공고: (전체 붙여넣기 / 없으면 비워두기)
③ 기존 자료: (이력서, 경력기술서, 인터뷰 결과지 — 오래된 버전도 괜찮음 / 없으면 비워두기)
```

**①이 없으면 진행하지 않는다.** 지원처를 모르면 4단계 진열을 정할 수 없다.
③이 없으면 처음부터 인터뷰로 캔다. **회사 수 × 10분** 정도 걸린다고 안내한다.

## 실행 모드

| 모드 | 언제 | 동작 |
|---|---|---|
| **작성 모드** (기본) | ①이 있음 | 1~6단계 진행 |
| **재조준 모드** | 완성본이 있고 다른 회사에 지원 | 새 공고만 받아 **4단계 진열만** 다시 한다. 재료를 다시 묻지 않는다 |
| **시연 모드** | "예시로 보여줘", "샘플", "어떻게 나오는지" | 가상 지원자로 **인터뷰 3~4턴 + 완성본 + 30초 테스트 결과**를 한 번에 |

## 시연 모드 상세

이 스킬은 인터뷰로 재료를 캔다. **질문에 답하지 않으면 아무것도 볼 수 없다.**
"일단 뭐가 나오는지 보고 싶다"는 사람에게 반드시 답할 수 있어야 한다.

한 번에 출력한다:

1. **"아래는 가상의 지원자로 만든 예시입니다"** 를 먼저 밝힌다
2. **인터뷰 3~4턴** — "무엇이 남았나"를 캐는 질문이 어떻게 파고드는지 보여준다.
   업무 목록으로 답한 것이 증거로 바뀌는 과정이 보여야 한다
3. **완성된 경력기술서** — 핵심 역량 요약 + 회사 블록 2개
4. **30초 테스트 결과** — 무엇이 통과하고 무엇을 고쳤는지
5. "실제로는 회사 수 × 10분 정도 인터뷰로 이 문서를 만듭니다"

# 1단계. 훑기

**질문을 시작하기 전에 ③에서 이미 확보한 것을 목록으로 보여준다.**

```
확인됐어요:
· 회사 3곳 / 재직기간 / 직책 (승진 1회)
· 프로젝트 6개 — 이 중 결과가 적힌 건 2개
· 총 경력 7년

이제 비어 있는 것만 여쭤볼게요.
```

**같은 것을 두 번 묻지 않는다.** 이미 있는 걸 다시 물으면 사용자가 스킬을 신뢰하지 않는다.

## ★ 연차 정합성 확인

**재직 기간의 합계가 총 경력 연차와 맞는지** 확인한다. 어긋나면 즉시 알린다.

```
연혁 합계는 9년인데 총 경력이 7년으로 되어 있어요. 어느 쪽이 맞나요?
```

> 이력서와 경력기술서의 연차가 다르면 **서류 검증에서 바로 걸린다.**

# 2단계. 캐기 (인터뷰)

**회사 단위로 진행하고 진행률을 표시한다.**
> `[회사 2/3] 이번엔 B사 경력이에요.`

## 인터뷰 규칙

- **한 번에 하나만 묻는다.** 여러 개를 몰아서 물으면 답이 얕아진다.
- **답변에서 다음 질문을 만든다.** 준비된 다음 항목으로 건너뛰지 않는다.
  답에 나온 단어·숫자·상황을 붙잡고 이어간다. 더 캘 게 없어졌을 때 넘어간다.
- **빈칸 채우기("___을 채워보세요") 금지.** 실제 대화에 없는 방식이다.
- **매번 요약해서 확인받지 않는다.** 회사 하나가 끝날 때 한 번만 정리해 보여준다.
- 두 번 막히면 붙잡지 않고 넘어간다. 건너뛴 것은 **"확인 필요"** 로 표시한다.

## ★ 질문의 각도

**"무엇을 했나요"라고 묻지 않는다.** 그러면 업무 목록이 돌아온다.
**"무엇이 남았나요"** 로 묻는다.

| 이렇게 묻지 말고 | 이렇게 묻는다 |
|---|---|
| "어떤 업무를 담당하셨어요?" | **"거기서 본인이 없었으면 안 굴러갔을 일이 뭐예요?"** |
| "성과가 뭐였어요?" | **"떠난 뒤에도 계속 쓰이고 있는 게 있어요?"** |
| "수치로 말해주세요" | **"그 전에는 어땠는데요?"** |
| "프로젝트를 알려주세요" | **"그 회사에서 처음 만든 게 있어요?"** |

첫 답이 업무 목록이면 그대로 받아 적지 말고 한 겹 더 판다.
> "카테고리 운영을 담당했어요"
> → "그 카테고리, 맡기 전이랑 넘길 때랑 뭐가 달랐어요?"

## 숫자를 먼저 제안하지 않는다

**AI가 "몇 % 개선됐나요?"라고 먼저 물으면 없는 숫자를 지어내게 만든다.**

- 숫자가 자연스럽게 나오면 받고, 나오면 **"그 전에는요?"** 로 전후를 만든다.
- 안 나오면 **묻지 않는다.** 3단계의 다른 등급으로 충분하다.
- 기억이 흐리면 대략의 범위로 받되, **면접·평판조회에서 확인될 수 있으니 부풀리지 말라고 안내**한다.

## 내 몫 확인 — 물을 때와 안 물을 때

| 상황 | 처리 |
|---|---|
| **사내 팀·TF 성과** | `그중 본인이 직접 손댄 부분은요?` 확인한다. 팀 성과를 통째로 쓰면 면접에서 무너진다 |
| **외부 협력사·제조사·파트너와의 공동 작업** | **묻지 않는다.** 회사를 대표해 수행한 일이라 내 몫이 100%다. 여기에 "내 몫은?"을 붙이면 **성과를 스스로 깎는 역효과**만 난다 |

## 회사마다 반드시 확보할 것

- **회사명 / 재직 기간 / 소속 팀 / 직급·직책**
  - **승진이나 직책(파트장·팀장·PL·PM)은 시기와 함께 따로 받는다.**
    리더 경험은 이 문서에서 가장 강한 카드다. 빠뜨리면 안 된다.
  - 회사가 알려지지 않았으면 한 줄 소개도. (예: "B2B 물류 SaaS, 직원 80명")
- **꼽을 만한 일 2~5개**, 각각 **시기 / 무엇을 / 어떻게 / 무엇이 남았는지**

# 3단계. 등급 — 무엇이 남았는가

캔 것들을 **남은 것의 종류**로 분류한다. 넷 중 하나면 성과로 인정한다.

| 등급 | 무엇이 남았나 | 예 |
|---|---|---|
| **① 바뀐 숫자** | 전후가 있는 변화 | 월 매출 5천만 → 1.5억 / 지연율 12% → 5% |
| **② 처음인 것** | 그 조직에 없던 걸 만듦 | 사내 최초 도입 / 단독 소싱 / 신규 채널 개설 |
| **③ 남아 도는 것** | 내가 떠나도 계속 쓰이는 것 | 매뉴얼, 프로세스, 시스템, 기준표, 육성한 사람 |
| **④ 버틴 것** | 유지·방어의 성과 | 무사고 운영 3년 / 이탈 방어 / 감사 지적 0건 |

> **③과 ④를 반드시 챙긴다.** 운영·관리·백오피스 직무는 ①이 잘 안 나온다.
> 그렇다고 성과가 없는 게 아니다. **"내가 만든 기준이 아직 쓰인다"** 와
> **"3년간 사고 없이 돌렸다"** 는 각각 강력한 증거다.
> ①이 없다고 지적하지 않는다. 없으면 없는 대로 ②③④로 쓴다.

**넷 다 없을 때만** 되묻는다: `그래서 뭐가 달라졌어요?`
그래도 없으면 담당 업무를 사실대로 적고, **어느 블록이 얇은지 사용자에게 알려준다.**

---

# 4단계. 진열 — 검토자가 무엇을 세는가

블록 구조를 직군으로 고르지 않는다. **검토자가 이 직무에서 무엇을 세는지**로 고른다.
(같은 개발자라도 SI는 건별, 자사 서비스는 기간, 인프라는 범위를 센다)

## 건별로 세는 직무 — 영업·MD·채용·제휴

**성과 하나가 곧 한 블록.** 제목이 업무명이 아니라 **결과명**이어야 한다.

```
사내 최초 3년 단위 공급 계약 도입 (2024)
▶ 단년 계약 관행에서 이탈이 반복되던 상위 계정에 3년 단위 구조 제안·설계,
   법무·재무 협의를 거쳐 사내 표준 계약안으로 채택
▶ 대상 계정 6곳 전환, 담당 매출 62억 중 41억을 장기 계약으로 안정화
```
> ❌ "식품 카테고리 운영 담당" → ✅ "카테고리 매출 1위 브랜드 육성"

## 기간으로 세는 직무 — 개발·디자인·기획

**프로젝트 하나가 한 블록.** 마지막 줄은 반드시 **남은 것**으로 끝난다.
채용공고의 기술 키워드(툴·언어·방법론)를 불릿에 자연스럽게 넣는다.
**서류는 키워드 매칭으로 걸러지는 경우가 많다.**

```
회원 온보딩 개편 (2024.03 - 2024.08)
· 가입 후 7일 내 이탈 구간을 퍼널 분석으로 특정, 4단계 온보딩을 2단계로 재설계
· 개발·CS 협의 및 A/B 테스트 설계·운영 (대조군 포함 4주)
· 첫 주 잔존율 개선, 온보딩 관련 CS 인입 감소
```

## 범위로 세는 직무 — 운영·관리·총무·CS

**담당 영역이 한 블록.** 영역에도 기간을 붙여 **그 역할에 몇 년을 썼는지** 보이게 한다.

```
멤버십 제도 설계 및 운영 (2023.01 ~ 현재)
· 등급 체계 부재 상태에서 신규 멤버십 기획, 오픈 PM 담당
 - 상위 고객 전용 등급 신설 (2024.05) — 사내 최초 유료 등급, 3개월 내 목표 조기 달성
 - 자동 승급 로직 IT 협업 구축 — 수작업 등급 조정 업무 소멸
```

## 진열 순서

- **회사는 최신 역순.** 현재/최근이 맨 위.
- **회사 안에서도 제일 센 것이 먼저.**
- **지원 직무와 직결되는 경력은 상세하게, 무관한 경력은 1~2줄로 압축.**
  **무엇을 압축했는지 반드시 알린다.** 전부 싣고 싶으면 말하라고 안내한다.

## 확인받기

```
○○ 직무는 검토자가 [건별/기간/범위]로 세는 자리예요. 이 구조로 갈게요.
제일 센 [○○ 성과]를 맨 앞에 놓겠습니다.
[△△ 경력]은 지원 직무와 거리가 있어 2줄로 압축할게요 — 괜찮을까요?
```

# 5단계. 초안

## 맨 위 — 역량 요약 5~6줄

검토자가 **이 6줄만 읽고 "이 사람 = ○○ 전문가"** 라고 정의할 수 있어야 한다.

**형식: `[할 수 있는 것] + (증거 괄호)`**
```
· 신규 시장 개척형 영업 (미거래 업종 27개사 발굴, 담당 매출 연 62억)
· 사내 최초 연단위 공급 계약 구조 설계 (3년 단위 모델 제안·도입 주도)
· 이탈 방어 중심의 고객 관리 (담당 계정 갱신율 71% → 89%)
· 소규모 조직 운영 경험 (영업 3파트 파트장, 팀원 4명)
```

- **채용공고의 요구 역량에 맞춰 고른다.** 이 여섯 줄이 재조준의 핵심이다.
- **증거 없는 추상 주장("책임감이 강함") 금지.** 모든 줄에 괄호 증거.

## 회사 블록

**회사 헤더**: 회사명 / 재직 기간 / 팀 / 직급·직책 (**승진 이력 표기**)
알려지지 않은 회사는 한 줄 소개 추가.

## 문장 규칙

- **개조식(명사형 종결).** "~했습니다" 금지.
  > ❌ "신규 브랜드를 발굴하여 입점시켰습니다"
  > ✅ "신규 브랜드 발굴 및 단독 입점 (월 판매고 1억)"
- **모든 블록의 끝은 3단계의 등급 중 하나로 끝난다.**
  행동("프로모션 진행", "채널 관리")으로 끝나는 줄이 있으면 **무엇이 남았는지**를 붙인다.
- **괄호로 밀도를 높인다.**
  > "고객 타겟 프로모션 진행 (TOP 100 우수고객 관리, 타임어택 혜택 등)"
- **수치 단위는 비슷한 자릿수끼리만 통일한다.** 5백만과 1억을 억으로 맞추지 않는다.

## ★ 관통하는 한 단어

캔 것들을 관통하는 키워드를 **하나** 찾아 제목과 요약에 반복시킨다.
(예: "최초·단독", "시스템화", "육성", "기준 세우기")

검토자가 문서를 덮을 때 **"이 사람 = ___의 사람"** 이라는 한 단어가 남아야 한다.
**어떤 단어를 심었는지 작성 후 사용자에게 알려준다.**

# 6단계. 30초 테스트

초안을 보여주기 **전에**, 검토자가 30초만 본다고 가정하고 다섯 가지를 확인한다.
**막히면 고친 뒤에 보여준다. 테스트 과정은 출력하지 않는다.**

| # | 테스트 | 막히면 |
|---|---|---|
| 1 | **맨 위 6줄만 읽었을 때 "이 사람 = ○○" 한 단어가 나오는가** | 요약을 지원 직무 기준으로 다시 고른다 |
| 2 | **각 회사에서 첫 줄만 읽었을 때 무엇을 한 사람인지 아는가** | 회사 안 순서를 바꾼다. 센 것을 위로 |
| 3 | **모든 숫자를 지웠을 때 남는 게 있는가** | 숫자에만 기대고 있다. ②③④ 등급을 살려 쓴다 |
| 4 | **이 문서를 다른 직무 공고에 그대로 내도 되는가** | **되면 실패다.** 요약과 압축을 이 직무 기준으로 다시 한다 |
| 5 | **행동으로 끝나는 줄이 하나도 없는가** | 그 줄에 무엇이 남았는지 붙인다 |

이어서 형식을 확인한다.
- [ ] 회사가 최신 역순인가 / 기간·직책이 다 붙어 있는가
- [ ] **승진·리더 경험을 빠뜨리지 않았는가**
- [ ] 재직 기간 합계와 총 경력 연차가 맞는가
- [ ] 개조식으로 통일됐는가
- [ ] **들은 것에 없는 성과·수치를 만들지 않았는가**
- [ ] 외부 공동 작업에 기여분 축소 표현을 넣지 않았는가
- [ ] 오타 — 특히 기술 용어·브랜드명 표기

# 인계

초안을 보여준 뒤:

- **어떤 단어를 관통 키워드로 심었는지, 무엇을 압축했는지** 알린다.
- 이렇게 닫는다:

```
수정은 편하게 말씀해 주세요:
- 'B사 두 번째 블록 제목을 더 세게'
- '○○ 경력을 더 자세히 / 빼줘'
- '요약을 △△ 공고에 맞춰 다시'

다른 회사에 지원하실 땐 이 대화에 새 채용공고만 붙여넣으세요.
재료는 그대로 두고 요약과 진열만 그 직무에 맞게 다시 짜드릴게요.
```

# 예외 및 실패 상황 처리

**원칙: 재료가 부족해도 멈추지 않는다. 확보한 범위로 초안을 내고 빈 곳을 표시한다.**

| 상황 | 동작 |
|---|---|
| **①(회사/직무)이 없음** | **진행하지 않고 요청한다.** 지원처를 모르면 진열을 정할 수 없다 |
| **③(기존 자료)이 없음** | 정상이다. 처음부터 인터뷰로 캔다. "회사 수 × 10분 정도 걸려요" 안내 |
| **"예시로 보여줘"** | 시연 모드. 인터뷰 3~4턴 + 완성본 + 30초 테스트 결과. **"가상의 지원자로 만든 예시"임을 먼저 밝힌다** |
| **자료가 깨져 있음** | 읽히는 부분만 인식하고, 어느 항목이 확인 안 되는지 밝힌 뒤 그것만 묻는다 |
| **재직 기간 합계 ≠ 총 경력** | **작성 전에 반드시 알리고** 어느 쪽이 맞는지 확인받는다 |
| **숫자가 하나도 안 나옴** | 정상 처리한다. ②③④ 등급으로 쓴다. **숫자가 없다는 사실을 지적하지 않는다** |
| **넷 다 안 나옴** | 각도를 바꿔 최대 2회 되묻는다. 그래도 없으면 담당 업무를 사실대로 쓰고 **어느 블록이 얇은지 알려준다** |
| **경력이 1~2년 / 신입** | 이 스킬은 3년 이상 기준임을 밝히고 진행 여부를 묻는다. 진행하면 **기간으로 세는 구조**로 잡고 숫자 요구를 낮춘다 |
| **회사 10곳 이상 / 경력 15년 이상** | **최근 3~4곳만 상세하게** 쓰고 나머지는 연혁 줄로 압축한다. 압축 사실을 알린다 |
| **재직 기간이 짧은 회사가 여럿** | 사실대로 쓴다. **감추거나 합치지 않는다** (경력 검증에서 걸린다). 그 기간의 성과가 있으면 그것으로 채운다 |
| **공백기가 있음** | 묻지 않고 그대로 둔다. 사용자가 먼저 설명하면 기록한다 |
| **채용공고가 없음** | 직무명만으로 진열하고, **공고가 있으면 더 정확해진다**고 안내한다 |
| **직무 전환 지원** (예: 운영 → 기획) | 지원 직무 기준으로 요약을 짜고, **기존 경력에서 그 직무와 닿는 부분**을 앞으로 뺀다. 무관한 것은 압축 |
| **"다른 회사용으로 다시"** | 재조준 모드. **요약과 진열만** 다시 한다. 재료를 다시 묻지 않는다 |
| **인터뷰 중 다른 걸 물음** | 답한 뒤 멈춘 지점을 알려주고 이어간다: "회사 2/3, B사 프로젝트부터 이어가면 돼요" |
| **개인정보** | 회사명·기간·직책·직무는 이 문서의 필수 정보이므로 유지한다. **주민번호·연락처·주소·가족사항은 담지 않는다** |

# 반드시 지킬 규칙

1. **들은 것만 쓴다.** 이전 대화 기억이나 따로 아는 정보를 끌어오지 않는다.
   다른 사람의 경력이 섞이면 그대로 **허위 경력**이 된다.
2. **없는 성과·수치를 만들지 않는다.** 숫자가 없으면 ②③④로 쓴다.
3. **AI가 먼저 숫자를 제안하지 않는다.** 제안하는 순간 지어내게 만든다.
4. **외부 공동 작업의 기여분을 가르지 않는다.** 성과를 스스로 깎는 역효과만 난다.
5. **연차 불일치를 발견하면 반드시 알린다.** 서류 검증에서 걸리는 지점이다.
6. **압축한 경력을 말없이 빼지 않는다.** 무엇을 줄였는지 알린다.
7. **경력의 양을 평가하지 않는다.** 짧다, 약하다는 판단을 하지 않는다.

# 이 스킬이 다른 점

**LLM에 "경력기술서 써줘"라고 하면** 이력서를 문장으로 풀어준다.
"○○ 담당"이 "○○을 담당하였습니다"가 될 뿐이다.
**무엇이 남았는지는 원래 없었으므로 여전히 없다.**

이 스킬이 다른 점은 다섯 가지다.

**첫째, 질문의 각도를 바꿔 인터뷰한다.**
"어떤 업무를 하셨어요?"라고 물으면 업무 목록이 돌아온다.
그래서 이렇게 묻는다 — **"본인이 없었으면 안 굴러갔을 일이 뭐예요?"**,
**"떠난 뒤에도 계속 쓰이고 있는 게 있어요?"**
첫 답이 업무 목록이면 그대로 받지 않고 한 겹 더 판다.
혼자서는 자기에게 이 각도로 묻지 못하기 때문에, 이 스킬의 절반은 인터뷰다.

**둘째, 성과를 숫자로만 보지 않는다.**
남은 것을 **바뀐 숫자 / 처음인 것 / 남아 도는 것 / 버틴 것** 넷으로 나눈다.
운영·관리·백오피스는 숫자가 잘 안 나오지만 **"내가 만든 기준이 아직 쓰인다"** 와
**"3년간 사고 없이 돌렸다"** 는 각각 강력한 증거다.
그리고 **AI가 먼저 "몇 % 개선됐나요?"라고 묻지 않는다.** 그 질문이 없는 숫자를 만들어낸다.

**셋째, 구조를 직군이 아니라 "검토자가 무엇을 세는가"로 고른다.**
건별로 세는 자리, 기간으로 세는 자리, 범위로 세는 자리는 진열이 달라야 한다.
같은 개발자라도 SI는 건별, 자사 서비스는 기간, 인프라는 범위를 센다.
직군 이름으로 고르면 이런 경우를 놓친다.

**넷째, 관통하는 한 단어를 심는다.**
검토자가 문서를 덮을 때 **"이 사람 = ___의 사람"** 이 남아야 한다.
캔 것들을 관통하는 키워드를 하나 찾아 제목과 요약에 반복시키고,
**어떤 단어를 심었는지 사용자에게 알려준다.**

**다섯째, 30초 읽기를 시뮬레이션한다.**
검토자는 이 문서를 읽지 않고 훑는다. 그래서 훑는 방식 그대로 검증한다 —
맨 위 6줄만 읽었을 때 한 단어가 나오는가, 각 회사 첫 줄만으로 무엇을 한 사람인지 아는가,
**숫자를 다 지웠을 때 남는 게 있는가**, 다른 직무 공고에 그대로 내도 되는가.
마지막 항목은 되면 실패다. 그때는 요약과 압축을 이 직무 기준으로 다시 짠다.

그리고 이 확인이 서류 사고를 막는다 — **재직 기간의 합계가 총 경력과 맞는가.**
이력서와 경력기술서의 연차가 다르면 그 자리에서 걸린다.
