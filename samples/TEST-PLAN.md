# 타임리 테스트 계획

> 심사는 **새 대화창에서 처음 보는 입력**으로 이뤄진다 (재현 가능성 20점).
> 아래 케이스를 **각각 새 대화창에서** 돌려 통과 기준을 확인한다.
> 환경: `Making AI Beneficial Challenge` 스페이스 × **Solar Pro 4**

## A. 이력서 역량 진단기

| # | 입력 | 통과 기준 | 실패 신호 |
|---|---|---|---|
| A1 | `R1` 데이터엔지니어 | Python이 **레벨 4**로 판정되고 근거에 "6시간→40분"이 인용됨. `데이터 환경 표준화`가 레벨 5 | 수치 없는 항목이 레벨 4 이상 |
| A2 | `R3` 과장형 마케터 | **증명 실패 4건 이상** 탐지 ("문제 해결 능력", "다양한", "리더십 다수" 등). SQL·Python이 나열만 되고 업무 서술에 없음을 지적 | "다양한 채널 운영"을 레벨 3으로 인정 |
| A3 | `R2` 신입 | 정상 처리. 레벨 1~2 위주가 자연스럽다고 명시. **경력 부족을 결함으로 쓰지 않음** | "경력이 부족합니다" 류의 인신 평가 |
| A4 | (빈 입력) | 붙여넣을 내용을 예시와 함께 안내하고 종료 | 빈 결과표를 출력하거나 오류 메시지만 출력 |
| A5 | `J1` 공고를 넣음 | **채용공고임을 판별**하고 [채용공고 해부기]를 안내 | 공고를 이력서로 처리 |
| A6 | "3년차 개발자입니다" 한 줄 | 있는 만큼만 추출 + 입력이 짧다고 명시 | 없는 역량을 만들어냄 |
| A7 | `R1`을 **두 번 연속** 새 대화창에서 실행 | 레벨 판정이 **동일** | 실행마다 레벨이 달라짐 |
| A8 | `R1` + 이름/전화번호 추가해서 입력 | 결과에 **이름·연락처가 나오지 않음** | 개인정보 그대로 출력 |

## B. 채용공고 해부기

| # | 입력 | 통과 기준 | 실패 신호 |
|---|---|---|---|
| B1 | `J1` 직함 불일치 | **"실제로는 데이터 엔지니어에 가깝다"** 판정. "유관부서와 협업"에서 이해관계자 조율을 `implicit`으로 도출 | 직함 그대로 "데이터 분석가"로 판정 |
| B2 | `J1` | "소수 정예", "빠르게 성장 중"에서 **넓은 업무 범위**를 도출 | 회사 소개를 무시 |
| B3 | `J2` 담당업무만 | 자격요건 부재를 명시하고 **전부 implicit으로 도출**, 전체가 추론임을 상단에 표시 | 없는 자격요건을 만들어냄 |
| B4 | `J3` 마케터 | "매니저 없이 리드와 함께"에서 **자기주도성**을 도출. 우대사항(SQL)을 `nice`로 유지 | SQL을 `must`로 올림 |
| B5 | (빈 입력) | 안내 후 종료 | 빈 표 출력 |
| B6 | `R1` 이력서를 넣음 | **이력서임을 판별**하고 [이력서 역량 진단기]를 안내 | 이력서를 공고로 처리 |
| B7 | 모든 `implicit` 항목 확인 | 근거 인용과 **(추론)** 표시가 전부 붙어 있음 | 추론이 사실처럼 표시됨 |
| B8 | `J1`을 두 번 연속 실행 | `must`/`nice` 구분이 동일 | 구분이 뒤바뀜 |

## C. 지원 판단 리포트

| # | 입력 | 통과 기준 | 실패 신호 |
|---|---|---|---|
| C1 | `R1` + `J1` | **높은 적합도**. "Airflow"가 우대사항에서 충족으로. 계산 표가 출력됨 | 계산 과정 없이 점수만 |
| C2 | `R3` + `J3` | **낮은 적합도.** "ROAS 개선 경험"이 🔴. "다양한 채널 운영"을 충족으로 세지 않음 | 근거 없는 주장을 충족 처리 |
| C3 | `R2` 신입 + `J1` (경력 3년 요구) | 경력 조건 미충족을 사실대로 표시 + **우회 전략을 충실히 제시** | 신입이라고 분석을 포기 |
| C4 | `R1` + `J3` (직무 계열 다름) | "직무 계열이 달라 낮게 나오는 것이 정상"이라고 명시 + **전이 가능 역량 제시** | 그냥 낮은 점수만 |
| C5 | `R1`만 입력 (공고 없음) | **멈추지 않고** 이력서 단독 분석 결과를 내고 공고를 요청 | "두 문서가 필요합니다"만 출력하고 종료 |
| C6 | `J1`만 입력 | 공고 단독 분해 결과를 내고 이력서를 요청 | 위와 동일 |
| C7 | (빈 입력) | 안내 후 종료 | 오류 |
| C8 | `R1` + `R2` (둘 다 이력서) | **둘 다 이력서임을 판별**하고 안내 | 하나를 공고로 오인해 계산 |
| C9 | `J1` + `J3` (둘 다 공고) | 판별 후 **두 공고 비교표**를 대신 제공 | 오류 |
| C10 | 앞 스킬의 **JSON 출력**을 붙여넣기 | 추출을 건너뛰고 매칭만 수행 | JSON을 텍스트로 오인 |
| C11 | JSON에서 중괄호 하나 지우고 입력 | **파싱 실패로 멈추지 않고** 텍스트로 읽어 진행 | 파싱 오류로 종료 |
| C12 | `R1` + 요구역량이 안 잡히는 짧은 공고 | **0으로 나누지 않고** "계산 불가" 표시 + 원인 설명 | 0% 또는 오류 |
| C13 | `R1` + `J1`을 두 번 연속 실행 | 적합도 점수가 **동일하거나 ±3%p 이내** | 점수가 크게 흔들림 |

## 확인 순서 권장

1. **정상 케이스부터** (A1, B1, C1) — 기본 동작 확인
2. **핵심 차별점** (A2, B1, C2) — 이게 안 되면 독창성 점수가 안 나옴
3. **예외 케이스 전부** (A4~A8, B3, B5~B7, C5~C12) — 설계 체계성 30점 + 재현 가능성 20점
4. **재현성 확인** (A7, B8, C13) — 같은 입력 2회 실행

## 기록 방법

각 케이스 실행 후 결과를 `samples/results/` 에 저장해두면
프롬프트를 고쳤을 때 무엇이 나아졌는지 비교할 수 있다.

## 주의

- 모든 샘플은 **가상 인물·가상 기업**이다. 실제 이력서·실제 공고를 테스트에 쓰지 않는다
  (개인정보 및 저작권 — 규정 제5조 5항)
- 테스트도 크레딧을 소모한다. 1인당 20,000 크레딧 안에서 계획적으로 돌린다
