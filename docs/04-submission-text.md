## ⚠️ 작성 전 확인

- **스킬명은 타임리 스토어에 올린 이름과 100% 동일해야 한다.** 아래 이름으로 스토어에 올리거나,
  스토어 이름을 바꿨다면 여기도 같이 바꾼다.
- **1줄 요약은 50자 이내.** 아래 문안은 모두 50자 미만으로 맞춰져 있다.
- **참고 출처/저작권 항목**: 우리 스킬은 외부 데이터·API를 포함하지 않으므로 **비워둔다.**
  (아래 §4에 넣을 문구를 준비해뒀으니, 비워두기 불안하면 그걸 쓴다)
- **API Key 엑셀**: 외부 API 미사용이므로 **첨부하지 않는다.**

# 스킬 1 — 이력서 역량 진단기

### 스킬명
```
이력서 역량 진단기
```

### 스킬 1줄 요약 (50자 이내)
```
이력서에 쓴 경력이 실제로 증명되는지 검증하고 고칠 곳을 짚어줍니다
```

### (문제 정의) 이 스킬은 어떤 문제를 해결하나요?
```
[누가] 이직·취업을 준비하며 이력서를 반복해서 고치는 구직자입니다.

[얼마나 자주] 지원 시즌에는 주 2~3회 이력서를 손봅니다. 지원하는 회사마다
강조점이 달라 매번 다시 씁니다.

[어떤 작업에] 문장을 다듬고, 순서를 바꾸고, 표현을 고르는 작업입니다.

[시간은 얼마나] 한 번에 1~2시간, 주 3~6시간이 여기 들어갑니다.
(구직자 체감 기준 추정치입니다)

[무엇이 문제인가] 그 시간의 대부분이 '표현을 고르는 데' 쓰이고,
정작 중요한 질문은 확인되지 않은 채 넘어갑니다.
"내가 쓴 경력이 이 문서에서 증명되고 있는가?"

"다양한 프로젝트를 수행하며 문제 해결 능력을 길렀습니다"라고 쓰면
본인은 경력을 썼다고 생각하지만, 읽는 사람에게는 아무 정보도 전달되지 않습니다.
어떤 프로젝트였는지, 어떤 문제였는지, 어떻게 해결했는지가 전부 빠져 있기 때문입니다.

그리고 본인은 자기 이력서를 객관적으로 보지 못합니다. 몇 십 번을 다시 읽어도
'내가 아는 내 경력'이 머릿속에서 자동으로 채워지기 때문입니다.
그래서 증명에 실패한 문장을 스스로 찾아내지 못한 채, 그 위에서 표현만 계속 다듬습니다.
```

### (문제 해결 방식) 그 문제를 어떻게 해결하나요?
```
[해결 방식]
이 스킬은 문장을 고쳐주지 않습니다. 대신 '어느 문장이 증명에 실패했는지' 짚어냅니다.

1. 기술스택 나열 줄이 아니라 업무 서술 문장에서 역량을 추출합니다.
   "월 200만 건 로그 배치 파이프라인을 Python으로 설계" 한 문장에서
   기술(Python) + 직무능력(파이프라인 설계) + 도메인(대용량 처리) 세 개를 뽑습니다.

2. 모든 판정에 이력서 원문을 인용합니다. 인용을 붙이지 못하면 그 역량은 인정하지 않습니다.

3. 증명 실패 지점을 7개 유형으로 분류해 가장 먼저 보여줍니다.
   근거 없는 주장 / 범위 흐린 표현 / 결과 없는 활동 / 나열만 된 스킬 /
   카테고리 편중 / 정체 구간 / 경력 공백

결과적으로 '표현을 다듬는 1~2시간'이 '어디를 고칠지 아는 10분'으로 바뀝니다.

[유사 스킬 및 차별점]
이력서 첨삭·분석 계열의 스킬은 이미 여러 개 존재합니다. 차이는 세 가지입니다.

첫째, 방향이 반대입니다.
일반적인 첨삭은 문장을 매끄럽게 다듬어 줍니다. 그 과정에서 없던 형용사가 붙고
과장이 늘어납니다. 사용자는 자기가 쓰지 않은 표현을 이력서에 넣게 되고,
면접에서 그 문장에 대한 질문을 받으면 답하지 못합니다.
이 스킬은 고쳐주지 않고 짚어줍니다. 고칠 '방향'만 제시하고 문장은 본인이 씁니다.
없는 사실을 만들지 않으므로 면접에서 무너지지 않습니다.

둘째, 근거 인용을 구조적으로 강제합니다.
모든 역량 판정에 이력서 원문 문장이 함께 출력됩니다.
인용을 붙일 수 없으면 그 역량은 표에 올리지 않고 '증명 실패'로 분류합니다.
환각으로 없는 경력이 생기는 것을 구조가 막습니다.

셋째, 판정 기준이 표로 고정되어 재현됩니다.
"숙련도를 적절히 판단"이 아니라, 어떤 표현이 나오면 몇 레벨인지 표로 정해두었습니다.
"교육 이수"는 1, "참여·보조"는 2, "담당·수행"은 3,
"개선·최적화 + 수치"는 4, "설계·구축·리딩"은 5입니다.
레벨 4 이상은 수치나 구체적 결과가 원문에 있어야만 인정하고, 없으면 3으로 내립니다.
덕분에 같은 이력서를 여러 번 넣어도 같은 결과가 나옵니다.
```

### (스킬 동작 방식) 어떤 순서로 동작하나요?
```
[입력]
이력서, 경력기술서, 자기소개서, 포트폴리오 설명 중 무엇이든 텍스트로 받습니다.
여러 개가 들어오면 합쳐서 한 사람의 프로필로 처리합니다.

[처리]
1단계 구간 나누기 — 학력 / 경력(회사별) / 프로젝트 / 자격·어학 / 기타로 분리합니다.
  섹션 라벨이 없으면 시간 흐름과 문맥으로 나눕니다.

2단계 후보 뽑기 — 각 구간에서 역량 후보를 추출합니다.
  명사 나열이 아니라 동사구를 봅니다. 기술스택 줄에만 의존하지 않습니다.

3단계 분류 — 기술·도구 / 도메인지식 / 직무수행능력 / 대인·태도 / 자격·어학 / 정량조건
  6개로 분류하고, 표기 흔들림을 통일합니다(파이썬·Python3·python → Python).

4단계 레벨 판정 — 1~5 판정 표에 따라 결정합니다. 연차를 레벨로 환산하지 않습니다.
  레벨 4 이상은 수치·결과가 원문에 있어야 인정하고, 없으면 3으로 내립니다.

5단계 신선도 표시 — 현재 사용 중 / 3년 이내 / 3년 초과로 구분합니다.

6단계 증명 실패 지점 탐지 — 7개 유형으로 분류합니다.

[출력]
① 진단 요약 (추정 직무, 총 경력, 추출 역량 수, 증명 실패 건수, 세 줄 요약)
② 증명 실패 지점 표 — 가장 먼저 보여줍니다. 유형 / 원문 / 왜 증명이 안 되는가 / 고칠 방향
③ 역량 표 — 역량 / 분류 / 레벨 / 신선도 / 신뢰도 / 근거 원문 인용
④ 분류별 분포 — 어느 영역이 비어 있는지
⑤ 기계 판독용 JSON — 다른 스킬로 넘길 수 있는 구조화 데이터

[예외 처리]
원칙: 오류로 멈추지 않습니다. 부분 결과라도 냅니다.

· 입력이 비어 있음 → 붙여넣을 내용을 예시와 함께 안내하고 종료합니다.
· 한두 줄만 입력됨 → 있는 만큼만 추출하고, 입력이 짧아 정확도가 낮다고 표 상단에 명시합니다.
· 이력서가 아닌 문서 → 판단 근거를 밝히고 안내합니다.
  채용공고로 보이면 채용공고 분석 스킬을 안내합니다.
· 신입·무경력 → 정상 처리합니다. 학력·프로젝트·자격에서 추출하고,
  레벨 1~2 위주가 되는 것이 자연스럽다고 명시합니다. 경력 부족을 결함으로 쓰지 않습니다.
· PDF 복사로 줄바꿈이 깨짐 → 문맥으로 복원하고, 복원 실패 구간만
  "원문 확인 필요"로 표시한 뒤 나머지는 정상 진행합니다.
· 외국어 이력서 → 그대로 처리하고 결과는 한국어로 냅니다. 원문 인용은 원어를 유지합니다.
· 분량이 매우 김 → 경력·프로젝트를 우선 처리하고, 생략한 구간이 있으면 마지막에 명시합니다.
· 레벨 판정 근거가 애매함 → 추측하지 않고 낮은 쪽으로 판정하며 신뢰도를 낮음으로 표시합니다.
· 같은 역량이 여러 번 등장 → 하나로 합치고 가장 높은 레벨을 채택하며,
  근거는 그 레벨의 문장을 인용합니다.
· 개인정보 포함 → 추출은 하되 이름·연락처·주소·생년월일·주민번호는 출력하지 않습니다.

[사용하지 않는 것이 좋은 경우]
· 이력서 문장을 대신 써주기를 원하는 경우 — 이 스킬은 고칠 방향만 제시합니다.
· 특정 회사 합격 가능성 판정 — 공고와의 대조는 별도 스킬의 역할입니다.
```

# 스킬 2 — 채용공고 해부기

### 스킬명
```
채용공고 해부기
```

### 스킬 1줄 요약 (50자 이내)
```
채용공고 자격요건에 없는 숨은 요구사항을 담당업무에서 복원합니다
```

### (문제 정의) 이 스킬은 어떤 문제를 해결하나요?
```
[누가] 채용공고를 여러 건 검토하며 지원처를 고르는 구직자입니다.

[얼마나 자주] 지원 시즌에 주 10건 안팎의 공고를 봅니다.

[어떤 작업에] 공고를 처음부터 끝까지 읽고, 자격요건과 내 경력을 비교하고,
지원할지 판단하는 작업입니다.

[시간은 얼마나] 공고 1건을 자격요건까지 꼼꼼히 읽는 데 15~20분,
주 10건이면 주 3시간입니다. (구직자 체감 기준 추정치입니다)

[무엇이 문제인가] 주 3시간을 쓰고도 두 가지가 계속 일어납니다.

첫째, 자격요건만 읽고 판단하게 됩니다.
채용공고는 구조적으로 축약된 문서입니다. 담당업무 세 줄에 실제로는
열 개 가까운 역량이 숨어 있습니다.
"유관부서와 협업하여 요구사항을 정의" 한 줄은 실제로
이해관계자 조율 + 비기술 직군과의 커뮤니케이션 + 요구사항 문서화를 요구하는데,
자격요건 항목에는 한 글자도 적혀 있지 않습니다.
구직자는 자격요건 목록만 대조하고 "맞겠다" 또는 "안 맞겠다"를 판단합니다.

둘째, 서류를 통과해도 면접에서 막힙니다.
"담당업무에 있던 그 일, 해보셨어요?"라는 질문이 나오는데,
자격요건만 보고 지원했으니 대비가 되어 있지 않습니다.
면접 준비에 들어가는 몇 시간이, 애초에 무엇을 물어볼지 몰라서 헛돕니다.
```

### (문제 해결 방식) 그 문제를 어떻게 해결하나요?
```
[해결 방식]
공고 한 건을 필수 / 우대 / 숨은 요구사항으로 분해하고,
이 공고가 실제로 찾는 사람이 누구인지, 어디서 검증당할지까지 냅니다.

1. 자격요건 항목에 여러 역량이 섞여 있으면 쪼갭니다.
   "Python 기반 파이프라인 구축 및 운영 경험 3년 이상"
   → Python + 파이프라인 구축 + 운영·모니터링 + 경력 3년 이상, 네 개로 분해합니다.

2. 담당업무 문장에서 명시되지 않은 요구를 복원합니다. 8가지 복원 패턴을 지침에 표로 넣었습니다.
   "신규 서비스 런칭" → 0→1 경험, 불확실성 하 의사결정
   "기존 시스템 고도화" → 레거시 파악, 점진적 마이그레이션, 하위 호환 관리
   "소수 정예", "빠르게 성장 중" → 넓은 업무 범위, 직무 경계 모호함 감수
   "매니저 없이, 리드와 함께" → 자기주도성, 스스로 우선순위 설정

3. 직함을 믿지 않고, 요구역량의 무게중심으로 실제 직무를 판정합니다.

4. 강조도 1~2이면서 요구 레벨 3 이상인 항목에서 예상 검증 질문을 도출합니다.

[유사 스킬 및 차별점]
채용공고 요약·분석 계열의 스킬은 이미 존재합니다. 차이는 네 가지입니다.

첫째, 줄이는 것이 아니라 늘립니다.
공고 요약 스킬은 자격요건과 우대사항을 짧게 다시 써줍니다.
그건 이미 공고에 있는 내용이라, 읽는 시간은 줄지만 판단은 나아지지 않습니다.
이 스킬은 담당업무 세 줄에서 열 개의 숨은 요구를 복원합니다.
공고 원문에 없던 정보가 결과로 나옵니다.

둘째, 추론과 사실을 분리해서 표시합니다.
복원한 항목에는 전부 (추론) 표시와 근거가 된 원문 인용이 함께 붙습니다.
지원자가 "공고에 쓰여 있던 것"과 "추론된 것"을 혼동하지 않습니다.
이 구분이 없으면 지원자가 공고에 없는 조건 때문에 불필요하게 포기할 수 있습니다.

셋째, 직함을 믿지 않습니다.
요구역량의 무게중심으로 실제 직무를 판정합니다.
직함은 "데이터 분석가"인데 요구역량 대부분이 파이프라인 구축·운영이면
실제로는 데이터 엔지니어를 뽑는 공고라고 알려줍니다.
직함만 보고 지원했다가 면접에서 어긋나는 상황을 미리 막습니다.

넷째, NCS 직무기술서를 인식합니다.
공공기관·공기업 채용공고에는 직무기술서가 첨부되며,

· 둘 다 이력서 → 판별 결과를 밝히고 안내합니다.
· 둘 다 채용공고 → 판별 후 두 공고의 비교표를 대신 제공합니다.
· JSON 형식이 깨짐 → 파싱 실패로 멈추지 않고 텍스트로 읽어 필요한 정보를 추출합니다.

  이력서 프로필만 제공합니다.
· 직무 계열이 완전히 다름 → 정상 계산하되 낮게 나오는 것이 정상이라고 명시하고,
  전직 관점에서 전이 가능한 역량을 별도로 제시합니다.
· 신입·무경력 → 정상 처리합니다. 경력 조건 미충족은 사실대로 표시하되,
  학력·프로젝트·자격 기반 대응을 우회 전략에 충실히 제시합니다.
· 대응이 애매함 → 억지로 연결하지 않고 부분충족으로 낮춰 잡으며,
  애매한 이유를 판정 근거에 명시합니다.
· 요구역량이 0개여서 가중치 합이 0 → 0으로 나누지 않습니다.
  적합도 대신 "계산 불가"를 표시하고 원인을 설명합니다.
· 개인정보 포함 → 이름·연락처·주소·생년월일은 리포트에 출력하지 않습니다.

[사용하지 않는 것이 좋은 경우]
· 합격 여부 예측 — 이 스킬은 서류상 역량 대조만 하며, 채용 결과를 예측하지 않습니다.

# 스킬 4 — 지원동기 인터뷰어

### 스킬명
```
지원동기 인터뷰어
```

### 스킬 1줄 요약 (50자 이내)
```
질문 4개로 이야기를 꺼내 자소서 지원동기를 씁니다. 지어내지 않습니다
```

### (문제 정의) 이 스킬은 어떤 문제를 해결하나요?
```
[누가] 자소서 지원동기 문항 앞에서 첫 문장이 안 써지는 취업준비생과 이직 준비자입니다.

[얼마나 자주] 지원 시즌에 주 3~5개 회사에 지원하고, 회사마다 지원동기를 새로 씁니다.
지원동기는 거의 모든 자소서에 들어가는 필수 문항이라 매번 반복됩니다.

[어떤 작업에] 빈 화면을 열어 놓고 무슨 이야기를 쓸지 고르고, 문장을 만들고,
글자수를 맞추고, 다시 읽고 고치는 작업입니다.

[시간은 얼마나] 지원동기 한 편에 2~3시간이 들어가고,
그중 절반 이상이 "무슨 이야기를 쓸지 정하는" 단계에서 사라집니다.
(취업준비생 체감 기준 추정치입니다)

[무엇이 문제인가] 원인은 글솜씨가 아니라 소재를 못 찾는 것입니다.

지원자에게 경험이 없는 게 아닙니다. 있는데 꺼내지 못합니다.
"지원동기를 쓰세요"라는 막연한 요구 앞에서는 아무것도 떠오르지 않다가,
"이 직무를 하고 싶다고 처음 생각한 순간이 언제였어요?"라고 물으면
그제야 구체적인 장면이 나옵니다.

그래서 대부분 두 가지 중 하나로 끝납니다.

첫째, 어디에나 쓸 수 있는 글이 됩니다.
"귀사의 무한한 발전 가능성에 매료되어" 같은 문장은 회사 이름만 바꿔도 그대로 통합니다.
읽는 사람은 이 지원자가 우리 회사를 아는지 알 수 없습니다.

둘째, AI에게 통째로 맡깁니다.
결과물은 매끄럽지만 자기 이야기가 아닙니다.
그리고 면접에서 그 문장에 대한 질문을 받으면 답하지 못합니다.
자소서가 잘 써질수록 면접이 위험해지는 역설이 생깁니다.
```

### (문제 해결 방식) 그 문제를 어떻게 해결하나요?
```
[해결 방식]
쓰기 전에 묻습니다. 질문 4개를 한 번에 하나씩 던져 지원자의 이야기를 꺼내고,
답한 내용만으로 지원동기를 완성한 뒤, 그 글에서 나올 면접 질문까지 뽑습니다.

1. 질문 4개 — 직무·업계를 택한 계기 / 확신이 굳어진 경험 / 왜 이 회사인가 /
   입사 후 하고 싶은 것. 경력자에게는 이직 이유를 하나 더 묻습니다.
   반드시 한 번에 하나만 묻고, 답이 오면 2~3줄로 요약해 "이렇게 이해했는데 맞나요"로
   확인한 뒤 다음으로 넘어갑니다.

2. 막연한 답에는 되묻습니다.
   "성장 가능성이 커서"라는 답에는
   "그건 다른 회사에도 그대로 쓸 수 있는 말이에요. 여기만 해당되는 게 뭘까요?"라고
   다시 물어 구체적인 장면이 나올 때까지 파고듭니다.
   단 한 질문당 꼬리질문은 최대 2번으로 제한해, 답하는 사람이 지치지 않게 합니다.

3. 답이 다 모이면 정해진 구조로 씁니다.
   소제목 / 두괄식과 계기 / 확신 / 왜 이 회사 / 마무리.
   계기는 생각이 아니라 겪은 장면으로, 마무리는 막연한 다짐이 아니라 구체적인 약속으로.

4. 보여주기 전에 10개 항목을 스스로 점검하고 어긋난 부분을 고칩니다.

[유사 스킬 및 차별점]
자소서 작성·첨삭 계열 스킬은 이미 많습니다. 차이는 네 가지입니다.

첫째, 쓰기 전에 묻습니다.
대부분의 자소서 스킬은 요청을 받으면 바로 완성된 글을 냅니다.
문장은 매끄럽지만 그 글에는 지원자가 없습니다.
이 스킬은 인터뷰를 먼저 합니다. 지원자에게 경험이 없는 게 아니라 꺼내지 못하는 것이므로,
질문의 각도를 바꿔주면 소재가 나옵니다.

둘째, 지어내지 않는 것이 규칙이 아니라 구조입니다.
답한 내용만으로 쓰기 때문에 소재가 모자라면 억지로 늘리지 않고 짧게 끝냅니다.
분량을 더 달라고 해도 늘리지 않고 "지금 소재로는 이 정도가 가장 단단하다"고 설명합니다.
"경험이 없는데 만들어줘"라는 요청에도 지어내는 대신
"거창하지 않아도 돼요. 수업, 알바, 취미에서 이 일과 닿는 순간이 있었나요?"라고 다시 묻습니다.

셋째, 글자수 대신 문장 수로 분량을 맞춥니다.
AI는 한글 글자수를 정확히 세지 못합니다. "500자로 써줘"라고 하면 300자나 800자가 나옵니다.
그래서 자소서 문장 1개를 60~85자로 잡고, 문항 글자수 ÷ 62로 목표 문장 수를 계산합니다.
500자면 8문장, 700자면 11문장, 1000자면 16문장입니다.
문장이 60자에 못 미치면 새 문장을 늘리는 대신 언제·무엇·숫자를 더해 채웁니다.
분량이 안정적으로 맞고, 지원자는 마지막에 글자수만 확인하면 됩니다.

넷째, 면접까지 이어집니다.
다 쓴 뒤 그 글의 특정 대목에서 나올 면접 질문 3개를 뽑고,
하나는 반드시 "왜 하필 우리 회사냐"를 다시 파고드는 압박 질문으로 만듭니다.
답변은 쓰지 않습니다. 답을 먼저 읽으면 면접장에서 자기 말이 아니라 외운 문장이 나오기 때문입니다.

그리고 검증 항목에 이 한 줄이 들어 있습니다.
"이 글에서 회사 이름만 다른 회사로 바꿔도 말이 되는가. 말이 되면 실패다."
자소서가 실패하는 가장 흔한 이유를 이 한 줄이 막습니다.
```

### (스킬 동작 방식) 어떤 순서로 동작하나요?
```
[입력]
지원 회사·직무·신입/경력, 자소서 문항 원문, 채용공고 세 가지를 받습니다.
셋 다 비어 있어도 됩니다. 시작하기 전에 하나씩 물어봅니다.

첫 메시지를 보고 세 가지 모드 중 하나로 자동 진입합니다.
· 인터뷰 모드 (기본) — 질문 4개를 하나씩 물어 자소서를 완성합니다.
· 일괄 모드 — 지원자가 경험을 이미 길게 적어 보낸 경우,
  인터뷰를 건너뛰고 부족한 것만 되물은 뒤 바로 작성합니다.
· 시연 모드 — "예시로 보여줘"라고 하면 가상 지원자로 전체 흐름을 한 번에 보여줍니다.
  이 스킬은 대화형이라 질문에 답하지 않으면 결과물을 볼 수 없으므로,
  처음 써보는 사람이 흐름을 먼저 확인할 수 있게 두었습니다.
  시연 결과에는 "가상의 지원자로 만든 예시"임을 먼저 밝힙니다.

[처리]
STEP 0 시작 안내 — 답한 내용만으로 쓰고 지어내지 않는다는 것,
  질문이 4개이고 5~7분이 걸린다는 것을 먼저 알립니다.

STEP 1 신입·경력 확인과 회사 파악 — 경력이면 이직 이유 질문을 추가하고 톤을 바꿉니다.
  채용공고가 있으면 인재상과 직무 키워드를 3줄로 정리하고,
  없으면 지원자가 아는 만큼만 받습니다.
  확인되지 않은 회사 정보를 사실처럼 쓰지 않습니다.

STEP 2 인터뷰 — 질문 4개를 순서대로 하나씩 묻습니다.
  답이 오면 요약해 확인받고 다음으로 넘어갑니다.
  막연한 답에는 꼬리질문을 하되 한 질문당 최대 2번으로 제한합니다.
  지원동기에 쓸 것만 묻고, 실패·갈등·협업 같은 다른 문항용 경험은 묻지 않습니다.

STEP 3 작성 — 문항 글자수에서 목표 문장 수를 계산하고,
  소제목 / 두괄식과 계기 / 확신 / 왜 이 회사 / 마무리 구조로 씁니다.
  두괄식은 30~50자로 짧게, 나머지 문장은 60~70자가 되게 씁니다.

STEP 4 셀프 검증 — 보여주기 전에 10개 항목을 점검하고 어긋난 부분을 고칩니다.
  점검 과정은 출력하지 않습니다.

STEP 5 예상 면접 질문 3개 — 완성한 글의 특정 대목에서 나올 질문을 뽑습니다.
  하나는 반드시 "왜 하필 우리 회사냐" 압박 질문으로, 답변은 쓰지 않습니다.

STEP 6 마무리 안내 — 글자수 확인을 권하고, 수정 요청 예시를 알려줍니다.

[출력]
① 지원동기 본문 (소제목 + 목표 문장 수만큼의 본문)
② 문장 수 표시 — (문장 ○개 / 목표 ○개)
③ 예상 면접 질문 3개 — 각 질문마다 그 질문이 나오는 이유 한 줄
④ 마무리 안내 — 글자수 확인 권고와 수정 요청 방법

[예외 처리]
원칙: 인터뷰가 끊기더라도 그 시점까지 모인 것으로 결과를 냅니다.

· 입력이 완전히 비어 있음 → 입력 양식을 보여주고 첫 질문을 시작합니다.
  빈 입력도 정상 진입점입니다.
· "예시로 보여줘" → 시연 모드로 전환해 가상 지원자로 전체 흐름을 보여줍니다.
· 경험을 이미 길게 적어 보냄 → 일괄 모드로 전환해 부족한 것만 묻고 바로 씁니다.
· "그냥 알아서 써줘" → 거절하지 않고 이유를 설명한 뒤
  가장 중요한 두 질문만 물어 진행합니다.
· "경험이 없는데 만들어줘" → 지어내지 않습니다. 관점을 바꿔 다시 묻고,
  그래도 없으면 있는 것만으로 짧게 씁니다.
· 인터뷰 중 다른 것을 물음 → 그 질문에 답한 뒤 멈춘 지점을 알려주고 이어갑니다.
· 답이 계속 막연함 → 꼬리질문 2회 후 넘어가고, 마지막에 어느 부분이 약한지 알려줍니다.
· 문항이 지원동기가 아님 → 문항을 읽고 판단해 알려주고 진행 여부를 묻습니다.
· 문항 여러 개를 한 번에 넣음 → 지원동기에 해당하는 것을 골라 밝히고 진행합니다.
· 문항에 글자수가 없음 → 500자 기준으로 쓰고 그렇게 잡았다고 밝힙니다.
· 글자수가 특이함 → ÷62 공식으로 계산하고, 200자 미만이면 3문장을 하한으로 둡니다.
· 채용공고 대신 엉뚱한 문서 → 판단 근거를 밝히고 공고 없이 진행할지 묻습니다.
· 회사를 전혀 모름 → 추측하지 않습니다.
  회사 부분을 직무·업계 이야기로 대체하고, 조사 후 그 문장만 채우도록 안내합니다.
· 개인정보를 말함 → 자소서 본문에 넣지 않습니다.

[사용하지 않는 것이 좋은 경우]
· 지원동기 외 문항 (성장과정, 실패경험, 갈등경험) — 이 스킬은 지원동기 전용입니다.
· 이미 쓴 자소서의 첨삭 — 이 스킬은 백지에서 인터뷰로 시작하는 구조입니다.
· 경험을 지어내 채우기 — 답한 내용만으로 쓰며, 없으면 짧게 끝냅니다.
· 면접 답변 준비 — 질문만 뽑고 답변은 지원자가 직접 생각하게 둡니다.
```

비워두기가 불안하면 아래를 넣는다:

```
외부 스킬, 공공데이터 API, 제3자 데이터셋을 활용하지 않았습니다.
