# 채용공고 요구역량 분해기

채용공고를 **구조화된 요구역량 목록**으로 바꿉니다. 이 스킬의 진짜 가치는
**공고에 안 쓰인 것을 찾아내는 것**입니다.

공고는 구조적으로 **축약된 문서**입니다. 담당업무 3줄에 실제로는 10개의 역량이 숨어 있습니다.
필수/우대만 옮겨 적는 것은 이 스킬이 하는 일이 아닙니다.

## 입력

채용공고 전문. 회사소개, 담당업무, 자격요건, 우대사항, 근무조건 등 있는 대로.
링크가 아니라 **텍스트**로 받습니다.

## 처리 절차

### 1단계 — 블록 식별
공고를 블록으로 나눕니다: 회사·팀 소개 / 담당업무 / 자격요건 / 우대사항 / 근무조건 / 전형절차.
라벨이 없으면 문맥으로 분류합니다.

### 2단계 — 명시 요구사항 추출
자격요건 → `must`, 우대사항 → `nice`로 뽑습니다.
**한 항목에 여러 스킬이 섞여 있으면 쪼갭니다.**

- 원문: "Python 기반 데이터 파이프라인 구축 및 운영 경험 3년 이상"
- 분해: `Python`(TECH, must) + `데이터 파이프라인 구축`(TASK, must) + `운영·모니터링`(TASK, must) + `경력 3년 이상`(COND, must)

### 3단계 — 숨은 요구사항 추론 ⭐

**담당업무 문장에서** 명시되지 않은 필요 역량을 뽑습니다. `requirement: implicit`으로 표시.

| 공고에 이렇게 쓰여 있으면 | 실제로 필요한 것 |
|---|---|
| "유관부서와 협업하여" | 이해관계자 조율, 비기술 직군과의 커뮤니케이션 |
| "신규 서비스 런칭" | 0→1 경험, 불확실성 하 의사결정, 빠른 우선순위 조정 |
| "기존 시스템 개선" | 레거시 코드 파악, 점진적 마이그레이션 |
| "데이터 기반 의사결정" | 지표 설계, SQL, 결과 해석 및 설득 |
| "소수 정예", "빠르게 성장 중" | 넓은 업무 범위, 직무 경계 모호함 감수 |
| "매니저 없이", "리드와 함께" | 자기주도성, 스스로 우선순위 설정 |

회사 소개·팀 소개에서도 단서를 찾습니다. 조직 규모와 성장 단계가 요구 역량을 바꿉니다.

### 4단계 — 요구 레벨 판정
지원자에게 요구하는 숙련도를 1~5로 판정합니다. (기준은 이력서 추출기와 동일)

- "이해하고 있는 분" → 2
- "경험이 있는 분", "수행 가능한 분" → 3
- "개선한 경험", "최적화" → 4
- "설계", "구축", "리딩", "표준을 만들" → 5

### 5단계 — 강조도 판정
공고 안에서의 비중을 `priority` 1~3으로 매깁니다.
- 반복 언급, 자격요건 최상단, 담당업무 첫 줄 → 1
- 일반적인 자격요건 항목 → 2
- 우대사항 말미, "있으면 좋음" → 3

### 6단계 — 진짜 원하는 사람 한 문장
분해 결과를 종합해 **"이 공고가 실제로 찾는 사람"** 을 한 문장으로 씁니다.
공고 제목이 아니라 **요구역량의 무게중심**으로 판단합니다.
(예: 직함은 "데이터 분석가"인데 요구역량 대부분이 파이프라인 구축 → 실제로는 데이터 엔지니어에 가까움)

## 출력 형식

### ① 공고 요약

> **{직무} · {회사 유형/규모 추정}**
> **이 공고가 실제로 찾는 사람**: (한 문장)
> **주의 신호**: 요구범위 과다, 직함-업무 불일치, 조건 모호 등 발견 시

### ② 요구역량 표 (must → nice → implicit, 각 그룹 내 priority 순)

| 요구역량 | 분류 | 구분 | 요구레벨 | 강조도 | 근거 (원문 인용) |
|---|---|---|---|---|---|
| Python | TECH | must | 4 | 1 | "Python 기반 데이터 파이프라인 구축 및 운영 경험 3년 이상" |
| 이해관계자 조율 | SOFT | implicit | 3 | 2 | (추론) "유관부서와 협업하여 요구사항을 정의" |

`implicit` 항목의 근거에는 **(추론)** 을 반드시 표시합니다.

### ③ 예상 검증 포인트

면접·서류에서 실제로 확인당할 항목을 요구역량에서 도출해 3~5개.

| 검증 포인트 | 어떤 요구역량에서 나오는가 | 준비 방향 |
|---|---|---|

### ④ 기계 판독용 JSON

````json
{
  "job": { "title": "", "real_role": "", "company_stage": "", "warnings": [] },
  "requirements": [
    { "name": "", "raw": "", "category": "", "requirement": "must",
      "level": 3, "priority": 1, "evidence": "", "confidence": "" }
  ],
  "check_points": [ { "point": "", "derived_from": "", "prep": "" } ]
}
````

> 이 JSON을 **[역량 매칭 리포트]** 스킬에 넣으면 이력서와의 적합도를 계산할 수 있습니다.

## 반드시 지킬 규칙

1. **필수와 우대를 섞지 않습니다.** 공고가 우대사항에 넣은 것을 필수로 올리면 지원자가 불필요하게 포기합니다. 구분이 애매하면 `nice`로 둡니다.
2. **추론은 반드시 표시합니다.** `implicit` 항목에 근거 인용과 **(추론)** 표시가 빠지면 안 됩니다. 지원자가 공고에 있는 말로 착각하면 안 됩니다.
3. **축약을 보정하되 창작하지 않습니다.** 담당업무에 근거가 있는 것만 `implicit`으로 뽑습니다. 직무 일반론에서 끌어오지 마세요.
4. **회사를 평가하지 않습니다.** "주의 신호"는 공고 텍스트에서 관찰되는 사실만 적습니다. 회사 평판·추측 금지.
5. **차별 소지 조건은 그대로 옮기지 않고 표시합니다.** 나이·성별·용모·혼인 등 조건이 있으면 요구역량으로 등록하지 말고 "주의 신호"에 기록합니다.
