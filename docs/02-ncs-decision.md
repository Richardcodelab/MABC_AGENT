# NCS 활용 방식 결정

> 2026-08-27 · 상태: 결정됨

## 질문

NCS의 KSA(지식·기술·태도)를 스킬에서 불러올 수 있어야 하는가?

## 결정

**런타임 API 호출은 하지 않는다. 사용자가 붙여넣는 NCS 직무기술서에서 KSA를 받는다.**

## NCS 구조

```
대분류 → 중분류 → 소분류 → 세분류(= 직무, 표준은 여기서 개발됨)
  └ 능력단위 (능력단위코드, 능력단위명, 수준 1~8, 정의)
      └ 능력단위요소
          └ 수행준거
          └ 지식 (K) · 기술 (S) · 태도 (A)   ← KSA는 이 깊이에 있다
      └ 적용범위 및 작업상황 / 평가지침 / 직업기초능력
```

## API 호출을 배제한 이유

### 1. 입자 크기 불일치 (결정적)

KSA는 키워드가 아니라 **서술문**이다.

| NCS KSA 예시 | 이력서 표현 |
|---|---|
| 지식: "요구사항 분석 기법에 대한 지식" | "고객사 요구사항 정의서 작성 및 검수" |
| 기술: "요구사항 명세서 작성 기술" | 〃 |
| 태도: "고객 요구를 정확히 파악하려는 적극적 태도" | (이력서에 이런 문장은 없다) |

서술문 대 서술문 매칭은 의미 비교가 필요하고, 그건 표준 어휘를 쓰는 이점(표기 고정, 누적 비교)을 없앤다.
특히 **태도(A)는 이력서에서 검증 자체가 불가능**하다.

### 2. 도구명 부재

NCS는 기술 중립적으로 서술되어 `Python`, `AWS`, `Figma`, `React` 같은 도구명이 거의 없다.
민간 채용공고 요구사항의 상당 부분이 도구명이므로 **매칭 대상의 절반을 못 덮는다.**

### 3. 프롬프트 용량

세분류 아래 능력단위, 그 아래 능력단위요소, 다시 그 아래 KSA 항목들 → 전체는 수십만 항목 규모.
노코드 스킬 프롬프트에 내장 불가.

### 4. API가 검색용이 아님

[한국산업인력공단_NCS 관련 정보 서비스](https://www.data.go.kr/data/15063879/openapi.do)
- 반환 필드: 능력단위코드, 능력단위명, 능력단위수준, 대·중·소·세분류명, 능력단위정의
- **KSA는 반환하지 않는다**
- 페이지 번호 기반 조회 (키워드 검색 아님) → "이 이력서에 맞는 능력단위 찾기"를 하려면
  전체를 사전 수집·인덱싱해야 함. 노코드 스킬 단독으로 불가능.

> KSA를 포함하는 것은 `고교직업교육과정 정보 서비스` 계열이나, 이는 고교 직업교육과정 범위로
> 일반 채용 매칭에 쓰기엔 범위가 맞지 않는다.

관련 데이터셋: [NCS 활용자료](https://www.data.go.kr/data/15086446/openapi.do) ·
[NCS 기준정보 조회](https://www.data.go.kr/data/15128213/openapi.do) ·
[국가직무능력표준 정보_GW](https://www.data.go.kr/data/15157547/openapi.do)

### 5. 규정상 허용 여부 — 정정

**공식 규정 제5조 3항은 공공데이터포털 API를 명시적으로 허용한다.**
따라서 NCS API 사용은 **규정 위반이 아니다.** 이 문서의 결론은 규정이 아니라 **위 1~4의 기술적 부적합**에 근거한다.

다만 사용 시 부수 리스크는 있다:
- 재현 가능성 20점 = "오류 없이 안정적으로 구동되는가"
- 제12조 3호: 제출물 미동작 시 해당 스킬 실격
- 심사 시 제출한 API Key로 최대 3회만 실행

→ 외부 API를 쓴다면 **호출 실패 시에도 완결된 결과를 내는 폴백**이 필수다.
우리는 1~4의 이유로 애초에 쓰지 않으므로 이 리스크 자체가 발생하지 않는다.

## 채택한 방식 — 직무기술서 경유

**2017년부터 302개 전체 공기업·공공기관이 NCS 기반 능력중심 채용을 시행한다.**
이들은 채용공고에 **직무기술서**를 첨부하며, 그 양식에는 **능력단위와 지식·기술·태도가 명시**되어 있다.

따라서:

- 사용자가 직무기술서를 붙여넣으면 **KSA가 통째로 입력된다** → API 불필요
- 그 기관이 **실제로 선택한** 능력단위이므로, NCS 전체에서 추측해 찾는 것보다 **정확하다**
- 민간 공고에는 직무기술서가 없으므로, NCS 모드는 **자동 감지 후 선택 적용**한다

참고: [NCS 직무기술서 목록](https://www.ncs.go.kr/blind/bl04/JdsptList.do)

## 구현

스킬 개수는 3개 유지. 2번·3번에 **NCS 모드**를 추가한다.

| 스킬 | 변경 |
|---|---|
| 이력서 역량 추출기 | 변경 없음 (이력서에는 NCS 정보가 없다) |
| 채용공고 요구역량 분해기 | 직무기술서 감지 시 능력단위·KSA를 **추론하지 않고 그대로 채택**, 능력단위코드 기록 |
| 역량 매칭 리포트 | NCS 모드에서 KSA 서술문 대 이력서 문장 매칭 규칙 적용. **태도(A)는 별도 처리** |

## 향후 (결선 MVP 단계에서 재검토)

노코드 제약이 없어지면:
- NCS 능력단위 목록을 사전 수집해 벡터 인덱싱 → 민간 공고도 능력단위로 정규화
- 워크넷/고용24 API 연동해 공고 자동 수집 → 일괄 적합도 랭킹

지금은 필요 없다.
