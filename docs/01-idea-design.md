# 아이디어 설계 — 이력서 × 채용공고 스킬 매칭

> 작성일 2026-08-27 · 최종 수정 2026-08-27

## 0. 정정 (2026-08-27)

이 문서 초안은 제출물이 "Timely AI 스킬 + 기획 요약서"라는 언론 기사를 근거로 작성됐다.
**실제 제출은 Timely AI 스킬 스토어에 스킬을 올리는 것만으로 끝난다.** 기획서는 쓰지 않는다.

이에 따라 아래 두 가지가 바뀐다.

- **직군을 좁히자는 3절의 제안은 철회한다.** 스토어에 올리는 스킬은 불특정 사용자가 쓰므로
  범용성이 오히려 장점이다.
- **3개 스킬을 원안대로 유지한다.** 다만 각 스킬이 **단독으로도 동작**해야 스토어에서 개별
  가치가 있으므로, 3번(매칭)은 1·2번의 JSON을 받을 수도 있고 **원문만으로도 동작**하도록 설계했다.

아래 1·2절의 "최고점 1개 심사" 분석은 기록으로 남긴다.

## 1. 원안과 문제점

원안:
1. 이력서 → 스킬 추출·정렬 SKILL
2. 채용공고 → 스킬 추출·정렬 SKILL
3. 1+2 매칭 SKILL

### 문제: 제출 규칙과 충돌

대회는 **제출한 최대 3개 중 점수가 가장 높은 1개만** 대표작으로 심사한다.
원안은 **파이프라인**이라 각 조각이 혼자서는 완결되지 않는다.

| 심사자가 이것만 본다면 | 결과 |
|---|---|
| 3) 매칭 | 1), 2)가 없으니 **동작 안 함** → 치명적 |
| 1) 이력서 추출 | "요약 기능 아닌가?" → 차별성 약함 |
| 2) 공고 추출 | 위와 동일 |

**결론: 3개는 파이프라인 단계가 아니라, 각각 혼자 완결되는 서로 다른 3개의 각도여야 한다.**

## 2. 재구성안

각 스킬이 **입력을 받아 그 자리에서 완결된 산출물**을 낸다. C는 A·B를 호출하는 게 아니라 **내부에 전부 내장**한다.

### A. 공고 해부 스킬 — `채용공고 → 요구역량 분해서`
- **입력**: 채용공고 텍스트 1건 (붙여넣기)
- **출력**: 필수/우대 역량 분리 · NCS 능력단위 매핑 · 숨은 요구사항 · 예상 면접 질문
- **단독 가치**: 공고만 있으면 즉시 쓸모 있음. 이력서 불필요.

### B. 이력서 진단 스킬 — `이력서 → 역량 프로필 + 공백 진단`
- **입력**: 이력서 PDF/텍스트 1건
- **출력**: NCS 기준 역량 프로필 카드 · 근거 문장 인용 · **약점/공백 + 보완 액션**
- **단독 가치**: 공고 없이도 "내 경력의 현재 좌표"를 알려줌.

### C. 적합도 리포트 스킬 ⭐ **대표작** — `이력서 + 공고 → 지원 판단 리포트`
- **입력**: 이력서 1건 + 공고 1건
- **출력**: 적합도 점수 · **매칭/미스매칭 근거 표** · 지원 시 강조할 문장 · 부족분 보완 전략
- **단독 가치**: A·B 로직을 내부에 전부 포함하므로 **이것 하나만 봐도 완결**.

> A·B는 C의 *부품*이 아니라 C의 *축약판*이다. 순서상 C에 가장 공을 들이고, A·B는 C의 프롬프트를 잘라 만든다.

## 3. 필요한 데이터

### 3.1 채용공고 API — **예선에는 불필요**

구직자의 실제 행동은 "공고 DB 탐색"이 아니라 **"지금 이 공고에 지원할지 판단"** 이다.
입력은 사용자가 붙여넣는 텍스트로 충분하며, 이게 오히려 실사용 시나리오에 정확히 맞는다.

API를 붙이면 인증키·XML 파싱·실패 처리가 들어오는데 노코드에서 리스크만 커지고 심사 점수는 안 오른다.

- **예선**: 붙여넣기 입력 ✅
- **결선 MVP**: 워크넷/고용24 API 연동으로 "조건 맞는 공고 자동 수집 → 일괄 적합도 랭킹" 확장 (로드맵으로 기획서에 명시)

### 3.2 스킬 표준 사전 — **이게 진짜 승부처** ⭐

이력서: *"파이썬으로 데이터 파이프라인 3년"* / 공고: *"ETL 경험자 우대"*
→ **문자열로는 안 붙는다.** 중간에 표준 어휘가 필요하다.

이게 없으면 = LLM에 문서 2개 던지고 "비교해줘" = **차별점 0**.

| 데이터 | 제공처 | 가치 |
|---|---|---|
| **NCS 국가직무능력표준** ⭐ | [한국산업인력공단 오픈 API](https://openapi.hrdkorea.or.kr/main), 공공데이터포털 | 대분류→중→소→세분류→**능력단위→능력단위요소→KSA(지식/기술/태도)**, 능력단위 수준(1~8). 공공기관·공기업 채용이 실제 NCS 기반이라 실무 정합성 있음 |
| **워크넷/고용24 채용정보** | [공공데이터포털 (한국고용정보원)](https://www.data.go.kr/data/3038225/openapi.do) | 실시간 채용공고 + 400여 직업 상세. XML/UTF-8, 회원가입 후 인증키 | 
| O*NET (미 노동부) / ESCO (EU) | 공개 다운로드 | 영문 스킬 온톨로지. 보조용 |

**NCS를 축으로 잡을 때의 이점**: 추출 결과가 "파이썬, 커뮤니케이션" 같은 뜬구름이 아니라
`능력단위코드 + 수준(레벨)` 로 떨어진다 → 기획서에 쓸 수 있는 한 줄이 생긴다.

> 노코드 제약: NCS 전체를 API로 실시간 조회하기 어렵다면, **직군 1~2개로 범위를 좁혀
> 관련 능력단위 목록을 스킬 프롬프트에 표로 내장**하면 된다. 예선에는 이걸로 충분하다.

### 3.3 평가셋 — **API보다 급하다** ⭐⭐

기획서에 **"정확도 87%"** 라고 쓸 수 있느냐가 심사를 가른다. 그러려면 정답이 있는 데이터가 필요하다.

- 가상 이력서 **8건** (직군 2개 × 경력 초/중/고 · 애매한 케이스 포함)
- 채용공고 **8건** (공개 공고를 참고하되 회사명·고유정보는 각색)
- 사람이 매긴 **정답 매칭 라벨** (적합/부분적합/부적합 + 이유)

용도: ① 프롬프트 튜닝 ② **기획서에 넣을 정량 지표** ③ 결선 데모 시연용

> 🔒 **실제 이력서 사용 금지.** 개인정보이며 데모 시연에서 사고가 난다. 전부 가상 인물로 작성한다.

## 4. 차별화 논리 — "그냥 ChatGPT로 되는 거 아닌가?"

심사자가 반드시 던지는 질문. 방어 논리 4가지:

1. **표준 어휘 고정** — NCS 능력단위 코드로 정규화. LLM에 맨입으로 물으면 매번 다른 단어가 나와 비교·누적이 불가능하다.
2. **근거 강제** — 모든 판정에 이력서/공고 **원문 문장을 인용**. 환각 방지 + 사용자 신뢰.
3. **비대칭 처리** — 이력서는 "과장", 공고는 "축약"되는 서로 다른 왜곡이 있다. 이걸 각각 보정하는 규칙을 스킬에 내장.
4. **측정된 성능** — 평가셋 기반 정확도 수치 제시. 대부분의 출품작에 이게 없다.
