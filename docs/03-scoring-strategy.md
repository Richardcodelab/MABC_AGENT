# 배점표 → SKILL.md 작성 전략

> 심사는 **`skill.zip`과 `SKILL.md` 문서를 기반으로** 이뤄진다.
> **문서를 잘 쓰는 것이 곧 점수다.** 아이디어만으로는 100점 중 30점밖에 못 받는다.

## 배점 해부

| 항목 | 배점 | 심사 질문 | SKILL.md에 무엇이 있어야 하는가 |
|---|---|---|---|
| 문제정의 및 실용성 | 30 | 실제 겪는 구체적 문제인가 / **반복 과업의 빈도·시간이 명확한가** | **수치가 박힌 문제 정의 섹션** |
| 설계 체계성 | 30 | **예외 입력·실패 상황 처리가 지침에 반영되었는가** / 역할·지시·출력 구조가 체계적인가 | **예외 처리 표** + 역할/절차/출력 3분할 |
| 재현 가능성 | 20 | 처음 보는 새 입력으로도 의도대로 동작하는가 / 오류 없이 안정적인가 | **판정 기준의 결정론화** + 폴백 규칙 |
| 독창성 | 20 | 접근·설계에 독창성이 있는가 / **기존 스토어 스킬 대비 차별점이 명확한가** | **차별점 명시 섹션** |

**설계 체계성 30 + 재현 가능성 20 = 50점이 "예외 처리와 견고성"이다.** 배점의 절반이다.

## 각 항목별 작성 지침

### 문제정의 30점 — 수치를 박는다

심사 질문이 "**빈도·시간이 명확한가**"이다. 형용사로는 점수가 안 나온다.

- ❌ "구직자들이 공고 검토에 많은 시간을 씁니다"
- ✅ "공고 1건을 자격요건까지 꼼꼼히 읽는 데 15~20분. 주 10건 지원 시 **주 3시간**.
  그중 실제 판단에 쓰이는 건 '내 경력과 겹치는가' 한 가지인데, 이걸 매번 처음부터 다시 한다."

**포함할 것**: 누가 / 무슨 과업을 / 얼마나 자주 / 한 번에 얼마나 걸리는지 / 그래서 이 스킬이 무엇을 줄이는지

> 수치는 **출처를 밝히거나 추정임을 명시**한다. 없는 통계를 지어내면 안 된다.
> "체감 기준", "가정" 이라고 쓰는 편이 허위 수치보다 낫다.

### 설계 체계성 30점 — 예외 처리를 표로 만든다

심사 질문이 "**예외 입력 및 실패 상황 처리가 지침에 반영되었는가**"이다.
**지침에 반영**되어야 한다 — 즉 SKILL.md 안에 글로 있어야 한다.

모든 스킬에 아래 형태의 표를 넣는다:

| 상황 | 스킬의 동작 |
|---|---|
| 입력이 비어 있음 | 무엇을 붙여넣어야 하는지 예시와 함께 안내하고 종료 |
| 필요한 입력 중 하나만 있음 | 있는 것만으로 가능한 부분 결과를 내고, 없는 쪽을 명시 |
| 입력이 너무 짧음 | 추출 가능한 만큼만 처리 + 신뢰도 낮음 경고 |
| 엉뚱한 문서 | 판단 근거를 밝히고 계속할지 물음 |
| 텍스트 깨짐 | 복원 가능한 범위까지 처리 |
| 판정 근거 부족 | 추측하지 않고 `확인 필요`로 표시 |

**핵심 원칙: 오류로 멈추지 않는다. 부분 결과라도 낸다.**
"입력이 잘못되었습니다"만 출력하고 끝나면 심사에서 미동작으로 읽힐 수 있다.

역할·지시·출력 구조는 **`역할 → 입력 → 처리 절차(번호) → 출력 형식 → 규칙 → 예외 처리`** 순서로 고정한다.

### 재현 가능성 20점 — 판정을 결정론으로 만든다

"처음 보는 새 입력으로도 **의도대로**" 동작해야 한다.
모델이 매번 다르게 판단하면 재현이 안 된다. **판정 기준을 표로 못 박는다.**

- ❌ "숙련도를 적절히 판단한다"
- ✅ 레벨 1~5 각각에 대해 **어떤 표현이 나오면 그 레벨인지** 표로 명시
- ✅ 점수 계산은 **공식으로** 제시하고 **계산 과정을 출력에 포함**

또한 **출력 형식을 고정**한다. 섹션 번호·제목·표 컬럼을 명시하면 입력이 달라도 출력 골격이 같다.

### 독창성 20점 — 차별점을 직접 쓴다

심사 질문이 "**기존 스토어 스킬 대비 나만의 차별점이 명확한가**"이다.
심사위원이 알아서 찾아주지 않는다. **SKILL.md에 직접 쓴다.**

각 스킬에 `## 이 스킬이 다른 점` 섹션을 넣고, **"그냥 LLM에 물어보는 것과 무엇이 다른가"** 에 답한다.

## 우리 3개 스킬의 차별점 (제6조 2항 대응)

> **제6조 2항**: 동일·유사한 제출물을 형식적으로 반복 제출하면 심사·집계에서 제외될 수 있다.
> 1번과 2번이 "추출 스킬"로 유사하게 보이면 위험하다. **문제 정의부터 다르다는 것을 드러낸다.**

| | 이력서 역량 추출기 | 채용공고 요구역량 분해기 | 역량 매칭 리포트 |
|---|---|---|---|
| **해결하는 문제** | 내 경력이 문서에서 **증명되고 있는가** | 이 공고가 **실제로 원하는 게 뭔가** | 이 공고에 **지원할 가치가 있는가** |
| **문서의 왜곡 방향** | **과장** — 부풀려 쓴다 | **축약** — 줄여서 쓴다 | 양쪽 왜곡을 동시 보정 |
| **핵심 처리** | 근거 검증 (인용 없으면 인정 안 함) | 숨은 요구 복원 (담당업무에서 추론) | 의미 기반 대응 + 가중 점수 |
| **출력의 성격** | 진단서 | 해설서 | 의사결정 리포트 |
| **사용 시점** | 이력서를 고칠 때 | 공고를 처음 볼 때 | 지원 버튼 누르기 전 |

세 스킬은 **입력도, 왜곡 보정 방향도, 사용 시점도 다르다.** 형식적 반복이 아니다.

## 제출 실무 체크

- [ ] 최종 스킬은 **타임리 편집창에서 제작**한다 (제5조 1항 — 타 서비스 제작 시 실격)
- [ ] 스토어 업로드 시 태그 **`mabc-final`**
- [ ] 스킬 1개당 **구글 폼 1회** + `skill.zip` 첨부
- [ ] 구글 폼용 **스킬명 / 1줄 요약 / 상세 설명** 별도 준비
- [ ] **새 대화창에서 처음 보는 입력**으로 테스트
- [ ] SKILL.md에 실명·연락처·인증키 없는지 확인
- [ ] 예시에 실제 채용공고 원문을 쓰지 않았는지 확인 (저작권)
- [ ] **완성 즉시 제출** (동점 시 선제출 우선)
