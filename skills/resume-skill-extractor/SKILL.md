# 이력서 역량 추출기

이력서를 **검증 가능한 역량 목록**으로 바꿉니다. 핵심 원칙은 하나입니다:
**모든 판정에는 이력서 원문 인용이 붙는다.** 근거를 못 찾으면 그 스킬은 쓰지 않습니다.

## 입력

이력서, 경력기술서, 자기소개서, 포트폴리오 설명 중 무엇이든. 텍스트로 받습니다.
여러 개가 들어오면 합쳐서 한 사람의 프로필로 처리합니다.

## 처리 절차

### 1단계 — 구간 나누기
원문을 섹션으로 분리합니다: 학력 / 경력(회사별) / 프로젝트 / 자격·어학 / 기타.
섹션 구분이 없으면 시간 흐름과 문맥으로 나눕니다.

### 2단계 — 후보 뽑기
각 구간에서 스킬 후보를 뽑습니다. **명사만 줍지 말고 동사구를 보세요.**

- ❌ "Python, AWS, 협업" ← 나열된 단어만 줍는 것
- ✅ "월 200만 건 로그를 처리하는 배치 파이프라인을 Python으로 설계" ← 여기서
  `Python`(TECH), `데이터 파이프라인 설계`(TASK), `대용량 데이터 처리`(DOMAIN) 3개가 나옴

**기술스택 나열 줄에만 의존하지 마세요.** 진짜 역량은 업무 서술 문장 안에 있습니다.

### 3단계 — 정규화
표기 흔들림을 통일합니다. `파이썬`/`Python3`/`python` → `Python`.
사내 용어·약어는 일반 명칭으로 풀되, `raw` 필드에 원표현을 남깁니다.

### 4단계 — 레벨 판정
아래 기준으로만 판정합니다. **연차가 곧 레벨이 아닙니다.**

| 레벨 | 이름 | 판정 근거가 되는 표현 |
|---|---|---|
| 1 | 노출 | "교육 이수", "학습", "사용해봄", 수업/자격 취득만 있음 |
| 2 | 보조 | "참여", "지원", "일부 담당", "보조" |
| 3 | 독립 | "담당", "수행", "운영", "개발" — 산출물이 명확 |
| 4 | 개선 | "개선", "최적화", "전환", "문제 해결" + **수치 변화** |
| 5 | 주도 | "설계", "구축", "표준화", "리드", "교육", "도입 결정" |

레벨 4 이상은 **수치나 구체적 결과가 원문에 있어야** 인정합니다. 없으면 3으로 내립니다.

### 5단계 — 신선도 표시
현재도 쓰는 스킬과 5년 전에 멈춘 스킬은 다릅니다.
`current`(현직에서 사용) / `recent`(3년 이내) / `past`(3년 초과)로 표시합니다.

### 6단계 — 공백 진단
경력 흐름을 보고 **약한 지점**을 짚습니다.
- 레벨 3 이상이 한 카테고리에 몰려 있음 (예: TECH만 높고 TASK가 없음)
- 최근 3년간 새로 습득한 스킬이 없음
- 경력 공백 기간
- 근거 없이 나열만 된 스킬이 많음 → "이력서에서 증명이 안 되고 있음"

## 출력 형식

### ① 요약

> **역량 프로필: {직무 추정}** · 총 경력 {N}년 · 추출 스킬 {N}개 (레벨3+ {N}개)
> 핵심 강점 3줄 요약

### ② 역량 표 (레벨 내림차순, 같으면 카테고리 순)

| 스킬 | 분류 | 레벨 | 신선도 | 근거 (원문 인용) |
|---|---|---|---|---|
| Python | TECH | 4 | current | "월 200만 건 로그 배치 파이프라인을 Python으로 설계, 처리시간 6h→40m 단축" |

### ③ 카테고리별 분포

각 카테고리에 레벨 3+ 스킬이 몇 개인지 표로. 편중을 눈에 보이게.

### ④ 공백 진단

| 지점 | 관찰 | 보완 액션 |
|---|---|---|

### ⑤ 기계 판독용 JSON

````json
{
  "profile": { "estimated_role": "", "total_years": 0 },
  "skills": [
    { "name": "", "raw": "", "category": "", "level": 1, "level_basis": "",
      "evidence": "", "years": 0, "recency": "", "confidence": "" }
  ],
  "gaps": [ { "point": "", "observation": "", "action": "" } ]
}
````

> 이 JSON을 **[역량 매칭 리포트]** 스킬에 그대로 넣으면 채용공고와의 적합도를 계산할 수 있습니다.

## 반드시 지킬 규칙

1. **근거 없는 스킬은 만들지 않습니다.** 이력서에 "리더십"이라고만 써 있으면 그건 근거가 아니라 주장입니다. `confidence: low`로 표시하고 레벨 1을 넘기지 마세요.
2. **추론한 것은 추론이라고 밝힙니다.** "쇼핑몰 백엔드 개발"에서 `REST API`를 추론했다면 `confidence: medium`, evidence에 추론 표시.
3. **과장을 보정합니다.** 이력서는 구조적으로 과장되는 문서입니다. "다수", "다양한", "등"처럼 범위가 흐린 표현은 레벨을 올리는 근거로 쓰지 않습니다.
4. **평가하지 않습니다.** "경력이 부족합니다" 같은 인신 평가 금지. 사실과 공백만 제시합니다.
5. **개인정보는 출력하지 않습니다.** 이름·연락처·주민번호·주소·생년월일은 결과에 포함하지 마세요. 회사명은 경력 맥락상 필요하면 유지합니다.
